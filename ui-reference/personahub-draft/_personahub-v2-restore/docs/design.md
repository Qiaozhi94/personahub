# PersonaHub V2 页面结构与功能设计

## 1. 设计结论

PersonaHub 的默认工作面应当以 Project 为根，以项目内容为视觉中心，以 Room 作为可持续的协作侧栏。

```text
左侧：定位项目对象
中间：阅读、判断和处理项目对象
右侧：与当前任务或 Room 协作
底部：观察执行、问题与验证
```

这套结构吸收 VS Code 的项目执行效率与 Obsidian 的文档、链接和知识组织方式，但增加 PersonaHub 独有的工作推进与可信交付维度。

## 2. 核心对象关系

```text
Space
├─ AI Members
├─ Skills
└─ Projects
   └─ Project
      ├─ Workspace：真实文件和执行边界
      ├─ Issue：目标与生命周期
      │  ├─ Primary Thread：完整活动线
      │  ├─ Rooms：阶段协作现场
      │  │  ├─ Room Thread
      │  │  └─ Work Graph
      │  ├─ Runs / Attempts
      │  ├─ Artifacts
      │  └─ Evidence
      └─ Project Knowledge
         ├─ Decisions
         ├─ Memory
         └─ Skill Candidates
```

约束：Room 是 Issue 某个阶段的协作与控制边界，不拥有第二套执行状态机；Run 仍是实际执行记录。

## 3. 一级工作面

### 3.1 开始中心

跨项目注意力入口，优先回答“现在最需要我处理什么”。包含待指派、审批、中断、不收敛、正在执行、最近完成和最近项目。

### 3.2 项目工作台

默认主页面。项目目录与虚拟项目对象位于左侧；中间统一打开文件、任务、Room、Artifact 和 Evidence；右侧 Room Dock 保持协作上下文；底部按需展开 Runs、命令、问题和验证。

### 3.3 能力库

管理 AI 成员、Squads、Workflows、Skills 和跨项目 Memory。AI 成员与 CLI 分离：成员描述能力和行为，CLI 只属于运行配置。

### 3.4 自动化中心

管理 Scheduled Issues、Webhook、执行队列和历史。自动化只负责创建或推进 Project 下的 Issue，不形成第二套任务体系。

### 3.5 设置与诊断

管理 CLI Runtime、模型认证、Workspace 权限、本地数据与健康诊断。GraphRun、NodeRun、SSE、SQLite 等内部概念默认不向普通用户暴露。

## 4. 项目工作台结构

### 4.1 全局范围与项目浏览器

工作区与项目是全局属性，在顶栏并列选择，只显示当前名称，不重复显示“工作区”“项目”标签。开始中心、能力库、自动化和设置仍能看到当前范围；项目浏览器只负责当前项目内部对象，不再承担项目切换，也不再增加“当前项目 / 项目资源”标题行。

项目浏览器提供四种对象树，“会话”作为驱动项目推进的基础入口默认排在第一位：

- 会话：按需要处理、正在进行、最近完成组织项目会话，并提供搜索、新建、打开、重命名、归档和删除入口。
- 资源：真实目录、项目文档、外部资料和 Workspace 状态。
- 产出：Artifacts、Evidence Summary、交付版本与验证结果。
- 知识：Decisions、Memory、Lessons 和 Skill Candidates。

顶栏已显示当前 Workspace 与 Project，资源树不再重复展示正常的“Workspace 可执行”卡片。可执行性只在异常、阻塞或用户主动查看运行环境详情时出现。

### 4.2 项目画布

所有项目对象通过标签页在同一画布打开：

- 文件/文档：全文阅读、Markdown 渲染、变化着色和引用关系。
- Task：目标、约束、完成要求、当前阶段、活动与下一步。
- Room：目标、成员、Work Graph、输入输出与归档回放。
- Artifact：内容、不可变 revision、来源和消费者。
- Evidence：验证结论、独立性、原始事件和风险边界。

### 4.3 Room Dock

Room Dock 是右侧常驻协作面，包含“会话”和“概览”两页：

- 会话：沿用原设计稿主会话的任务摘要、用户/Agent 消息气泡、系统事件、可展开执行步骤和底部输入框；本人发言靠右，暂停/恢复放在输入框内，“等待你指派”建议固定在输入框上方。
- 概览：参考 Clowder 状态右栏，按“会话信息（合并消息统计）→ Agent 状态 → 详细执行计划”排列。

指派与改派不设置独立管理按钮：等待状态由系统预填 `@成员` 指令，任意时刻也可在输入框输入 `@` 选择成员。证据动作贴近具体结论或缺失项，点击后预填验证指令。Room 不再增加“当前协作现场”标题行，会话/概览与左侧对象树标签保持同一水平线。

可信结果不是单独模块，而是三层结构：结论旁显示事实状态（已验证、同源验证、证据不完整等）；点击后在中间画布打开验证依据 / Evidence Summary；左侧产出树负责历史索引。完整页面按完成要求逐条连接系统记录、实际文件、Artifact revision 和验证者结论，不使用百分比信任评分。

被修改的 Markdown 与代码文件必须在首屏显示修改数量，并提供上一处 / 下一处跳转。正文使用左侧变更线、浅色背景和位置标签标出修改区块；代码以变更行范围为跳转单位。

引用的文件、Artifact 与 Evidence 直接从会话消息或项目树打开，不再单设“上下文”页。复杂 Graph、完整产物链和历史回放仍在中间画布展开。

### 4.4 执行面板

底部面板默认折叠，只在排障和验证时展开。包含队列、Runs、命令输出、Findings、测试与原始日志。

## 5. 关键交互原则

1. 切换文件不丢 Room：用户阅读不同内容时，当前协作上下文保持不变。
2. 任务像工作文档：Task 不是字段表格，而是目标、决策、活动、产出和验收条件的持续记录。
3. 证据可双向追溯：从结论能到原始事件，从文件或 Artifact 能看到由谁、在哪次尝试中产生。
4. 注意力高于时间：开始中心和任务树优先显示需要用户动作的项目对象，而不是最近更新时间。
5. 高级内部信息渐进披露：默认展示结果语言，诊断层才出现 Run ID、事件、命令和底层错误。

## 6. 原型覆盖

本版用一个静态 HTML 演示以下路径：

```text
进入项目
→ 从目录打开 PRD
→ 切到工作树并打开等待指派的任务
→ 查看 Room 深度视图
→ 在右侧暂停/恢复或发送指令
→ 打开 Artifact 与 Evidence
→ 展开底部执行面板
→ 切换到开始中心、能力库、自动化和设置
```

## 7. 暂不表达

- 真实文件编辑、Git 写操作和终端输入。
- 复杂拖拽、面板尺寸持久化和多编辑器分屏。
- 真实 Agent 执行、流式事件和后端数据。
- 完整创建表单、权限确认与错误恢复流程。
- 移动端和多人协作形态。
