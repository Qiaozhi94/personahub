# 界面实现说明

设计稿上曾经写在界面里、V3.30 起撤下来的约束与判断，按面归档，供实现时对照。随原型一起维护。

**这份文档的定位**：`design.md` 记的是「为什么这样设计」，这份记的是「实现这一块时不能违反什么」。界面上不再出现的每一条硬规则都在这里有一条，实现前逐条核对。

---

## 能力

| 元素 | 实现约束 |
|---|---|
| Skills 表 | 只有一种类型：填了 `steps` 的自动带 `#编组` tag，不填就是普通 skill。**不做两个类型**——用熟之后想固化步骤，两个类型就要「转换类型」，历史表现会跟着断。 |
| Skills 表 · 需要能力 | 写「这条做法至少需要执行者具备什么」，**不写「配哪个组合最好」**。后者会让固定角色从后门回来。 |
| Skills 表 · 已下发 | 它是**事实**（被翻译成了哪几个 adapter 的原生格式），**不是适用范围**。不得据此限制派工对象。 |
| Skills 详情 | 使用整页下钻，顶部显示 `能力 / Skills / 当前 Skill` 面包屑，详情状态下隐藏 Skills / MCP 顶层切换。正文只保留名称与说明、`id@version`、来源、最后更新、需要能力、下发状态及文件；不重复渲染 `SKILL.md` 已包含的步骤和完成标准。所有列表条目均须可打开。详情只读；要修改就打开磁盘文件或新建一版。 |
| 编组表现 | 是**一句现算的观察**（「@3 之后 12 次派工，验收一次通过 9 次」），不是评分。改一版就是另一段样本，所以版本号必须一起显示；不足 30 次标「样本不足」。 |
| 同名冲突 | 系统**不自动定优先级**。在使用者选定之前两个都不生效，也不下发到任何 adapter。 |
| 加严 / 放宽 | 插件只能把规则改严。**「放宽」在界面上没有表达，因为它不可能发生**——「什么算 Done」不能变成可以被插件关掉的东西。 |
| MCP 表 | 这一页是**意图**（声明装了什么）；adapter 的工具表是**结果**（实际带着什么，含 CLI 内置工具）。两处不一致时以运行时那份为准。「已同步到」列不可省——MCP 生效是 per-adapter 的。 |
| 插件贡献的 tab | 界面**不是插件画的**：插件在 manifest 里声明 `kind`、列名与动作，宿主渲染。动作只能引用宿主白名单。**插件能新增数据，不能新增交互范式**——需要第二种 `kind` 时那是宿主的一次性投入。 |
| 准入判据 | 缺了照样干活 → 可以在能力面开 tab；缺了派不了工（adapter）→ 归运行时，**不得声明 surface**。 |

## 运行时

| 元素 | 实现约束 |
|---|---|
| 机器列表 | 状态分两级报：**先机器，再 adapter**。机器掉线时它上面所有 adapter 都派不了工，而每个 adapter 自己的检查仍会显示「上次通过」。 |
| 同名 adapter | 两台机器上是两份东西：两份安装、两份登录态、两份额度。**列表不做跨机器合并**——合并之后「去重新登录」就不知道该在哪台机器上执行。 |
| 执行组合名 | 四元组 `adapter + 配置 + 模型 + 深度`，**执行位置不进组合名**（进身份快照的 `runtime_id`），否则同一个组合在两台机器上会变成两个名字。 |
| 组合总览 | **不提供排序、置顶、默认、别名**。列表天然诱导这四个动作，而它们全是偏好——一旦进来，adapter 就长成了被取消掉的「AI 成员」。 |
| adapter 状态灯 | 只有一个轴（能不能被派工），取最坏那一项，**不压成颜色梯度**；灯旁必须有一句话说明是哪一项坏了；per-project 差异不进灯。 |
| adapter 状态 | **只有在线 / 离线两种**，不在列表里评估额度——额度是另一个维度，单独成列。状态灯挂在 tab 上，不用点进去才知道哪个坏了。 |
| adapter 列表列 | `adapter · 状态 · CLI 版本 · 使用方式 · 额度 · 会话 · 可用组合`。订阅给结构化限额（`5h 41% · 周 62%`），按量写「不设上限」。 |
| 运行时的动作边界 | 运行时**只管执行资源的配置与状态，不做任务控制**。adapter tab 的「正在运行」是只读的——没有停止 / 结束 / 中止。停止执行进程在统计 · 监控，结束会话在会话本身。**判据：一个面的动作集合要和它的中心问题一致**；同一个动作不给两个入口，尤其当其中一个所在的面并不为它负责。 |
| 表单密度 | **只读事实用两列**（标签 76px + 值，一行一条），**可编辑字段才用上下两行**——前者是扫，后者是填。两块都短的分区并排，不竖着堆。 |
| 工具表 | **不只列 MCP**：CLI 自带的读文件 / 写文件 / 执行命令 / 网络请求也是工具，且状态会变（写文件请不请求授权、项目关网时网络可不可用）。列：`工具 · 类型 · 来自 · 状态 · 说明`。**类型**（MCP / 文件 / 命令 / 网络）说这是哪一类能力，**来自**说谁提供的（CLI 内置或哪个 MCP server）——两个问题不能挤进一列。全部工具在同一张表里看，不分区。**缺席逐条标**——「这个 adapter 不注入 MCP」这一句话要落到那四行上，笼统一句让人自己去对应。 |
| adapter 概览 | 卡片形式一行铺开：状态 / 接入方式 / 额度 / 可用模型。**「不支持」只在真有限制时出现**——摆一块空的和「它没有限制」是两回事，前者要人自己去推断。 |
| 使用方式 | **必选、无默认值**。给默认值等于替使用者决定一笔钱算不算支出。它决定额度行形态、告警阈值是否适用、统计进实付列还是订阅等价列。 |
| 接入方式（模型里叫「配置」） | **按需露出**：只有一个 CLI 真有多套接入方式（不同 `base_url` + 不同凭据）时，才给可增删的这一块。单一配法的 adapter（codex / claude-code）只给只读事实与终端登录命令——**它的凭据在 CLI 自己手里，PersonaHub 给不出可增删的东西**。
| 认证方式 | 一份接入只能有一种。想两种都用就建两份，否则失败时分不清是哪条路断的。 |
| 登录态 | **不代管**：token 由各 CLI 自己存，只做只读检查并给出终端命令。**这一支不得出现输入框**——出现输入框就说明抽象漏了。 |
| 额度 | 只报上游给的**时限额与周限额**，各带已用百分比与重置时间，取更紧的一个。**不折算成「还能派几次」**——固定系数换算出的整数是估算，不是事实。按配置分池，同配置下多个模型共用一份。 |
| 额度不足 | **不自动降级**。更换更低成本的组合会改变结果质量，那是使用者的质量判断。 |
| 做不到什么 | 每一条**写后果，不写能力位名字**。它是派工弹窗「结构性不具备」与验证独立性判定的落点。 |
| 能力边界 vs 故障 | 「能力不具备」**不计入失败率**，否则该指标不能再用于判断系统是否存在故障。 |
| 配置的改动 | **从下一次派工起生效**，正在跑的进程不受影响（换配置要冷启动新进程）。 |
| 删除一份配置 | 依赖它的执行组合从派工清单消失，但**历史执行记录保留当时的组合名**——证据链不因今天删了配置而断。 |
| 机器模型 | **不分本地与远程**：服务端不直接执行任务，每一次派工都落到某一台注册进来的执行机器上。机器一律用主机名，左栏不分组。 |
| 机器页分层 | 右侧是 tab：**概览排第一**，之后一个 adapter 一个 tab。概览装四个读数、adapter 列表与执行组合表；adapter tab 装**那一个 adapter** 的事（概览 · 运行中 · 工具）。两边不互相混装。 |
| adapter 列表 | 列：`adapter · 健康度 · CLI 版本 · 会话 · 可用组合`。点一行跳到它自己的 tab。**它和 tab 条不是重复**——tab 条给「切过去」，列表给「横着比」。 |
| 执行组合表 | 列：`组合 · 来自 · 使用方式 · 限额`。**不放状态列**：健康度已由 adapter 列表说完，同一个事实不写两遍。限额结构化展示（`5h 41% · 周 62%`）。 |
| 机器状态 | 不再单设「机器健康」。机器列表的点灯取其 adapter 状态的最坏值，具体原因在 adapter 列表中查看；系统诊断只显示执行机器汇总并跳转运行时，不复制逐机详情。 |
| 换机器 | 必须复位到概览：停在一个只有上一台机器才有的 adapter tab 上会显示空白。 |
| adapter 状态 | 状态灯挂在 tab 上，**不用点进去才知道哪个坏了**。 |
| 应用诊断 | 服务进程、SQLite、事件流、记忆检索等应用级探针只在系统诊断；每一行必须配一个可执行动作，不与机器点灯混算。 |
| 交付文案与数据表 | 界面只使用面向用户的正式文案，不出现原型、设计过程或实现阶段说明。每张数据表必须具有可访问名称、完整且不重复的正式字段、明确的状态与缺省值；禁止空表头、空数据单元格和破折号占位。 |
| 跨机器动作 | 额度告警阈值、暂停全部派工放在左栏页脚：**要改一条全局策略，不该先被迫选中某一个具体对象**。 |
| 暂停全部派工的归属 | 它**是派工闸门，不是任务控制**，因此不与上面「运行时不做任务控制」冲突：闸门决定新的派工能不能拿到执行资源，控制某个正在跑的进程仍然只在统计 · 监控。判据：动作的对象是**资源侧的准入**还是**某一个具体执行进程**。 |
| 高风险动作的统一形态 | 影响面跨项目或不可轻易回退的动作（暂停全部派工、删除配置、撤销授权）一律三块齐全：**这会动到什么 · 这不会动到什么 · 怎么恢复**，确认后必须留下一个常驻可见的状态与唯一恢复入口。只弹一句 toast 不算确认。 |
| 凭据输入 | 密钥、token 一律 `type="password"` 默认遮罩，另给显式的「查看」；**「保存后不回显」保护不到输入的那一刻**。全站不允许第二种写法。 |

## 统计

| 元素 | 实现约束 |
|---|---|
| 两个 tab | 用量是回顾，监控允许近实时，**两种口径不同屏**。监控必须显示刷新间隔与上次刷新时刻。 |
| 主维度 | **去向（任务）**，不是执行者。第二维度是用途（实现 / 验证 / 返工重试 / 上下文重传）；模型与执行组合退为单价基准，**不是排行榜**。 |
| 实付 vs 订阅等价 | **永不相加**。订阅消耗额度、不产生新增支出；API Key 每个 token 都是实际支出。等价一行必须标注「非实际账单」。 |
| Token 两列 | 缓存命中按折扣价计费；未命中是本次处理的输入加全部输出（**输出永远不进缓存**）。两列相加等于该行全部 token，四个维度的合计必须完全一致。 |
| 计价来源 | 必须显式标注：adapter 自报为**权威值**，本地价表折算为**估算值**。合并成单一数字后无法区分可信部分。 |
| 返工占比 | = 该任务 `step_kind` 为「返工重试」的 token ÷ 该任务全部 token（命中 + 未命中，**分母不排除缓存命中**）。加权后须等于「用途」维度的同名占比。 |
| 分页 | 每页 10 条，**合计行置顶且不随翻页变化**，与上方 KPI 逐格对得上。不设「本页合计」，不用「其余 N 个」聚合行。 |
| 第三级明细 | **不在统计模块内实现**：点任务行进入该任务的轨迹视图。 |
| 未归属项目 | `project_id` 为空的任务单独成行，**不分摊**——分摊等同于代替使用者完成归类。 |
| 监控收什么 | 只收**执行层**：正在执行、排队、失败率、失败列表。基础设施健康（SQLite / 事件流 / 磁盘）归运行时；额度是资源余量，也归运行时。 |
| 失败口径 | 只收录故障（进程异常退出、权限拒绝、执行超时、adapter 错误）。**「验证未通过」与「额度不足」不计入**——前者体现在用量页的「返工重试」，后者记录在自动化面。 |
| 样本不足 | 派工次数低于 30 次的执行组合必须标注：该样本量下 17% 与 10% 没有统计意义上的差异。 |
| 年度热力图 | 仅「近一年」下可选（0 单独一档 + 非零按四分位分四档）。不可用的形态**置灰而不是隐藏**。空白格 = 当日无派工记录，不是当日未计量。 |
| 正在执行 | 跨机器合并成一张表，**必须带「执行机器」列**——不说清是哪一台，「去停掉它」就不知道该在哪台机器上执行。 |

## 记忆

| 元素 | 实现约束 |
|---|---|
| 写入来源 | **只由已收敛的验收事件写入**，不从对话自动摘取。 |
| 写入约束 | `type × stance` 白名单：project fact 不允许 `claimed`，decision 只能 `confirmed`。违规写入**被拒绝并记录拒绝事件**，不静默丢弃。 |
| 三根轴 | 强度、验证于、引用**互不替代**，摆成三列，**不合成可信度分数**。引用次数永远不会自己提升强度，也不会写进「验证于」。 |
| 升为 confirmed | **只能由人来做**：机器可以验证一件事为真，「值得让以后所有任务都按它办」是判断，不是事实。自动入库不等于自动确认。 |
| 待复核 | **退出召回**，复核完成前不进入任何派工的上下文。引用次数不能替它续命。 |
| 退役 / 遗忘 | 退役可逆；遗忘必须**先退役**，且留墓碑（曾存在过、因何不可取回），**不保留正文**。 |
| 上下文过滤 | **不能是静默的**：装配时过滤掉几条、因为什么，必须压暗但在场。看验证结论时要能知道验证者当时看不到什么。 |
| 知识库列 | `强度 · 内容 · type · 层级 · 状态 · 验证于 · 最近召回 · 引用 · 采纳`。**「最近召回」不能省**——策略里设了退役阈值，界面就必须给这个数；超过阈值的行自己标出来。**「采纳」不能省**——引用是「被提到过几次」，采纳是「改变过几次做法」，决定要不要留一条看的是后者。 |
| 知识库 ↔ 知识图谱 | 两个面读取同一批数据，并支持双向定位：知识库条目可进入对应图节点，图节点可返回知识库条目。发布计划可以控制功能开放时间，但最终页面与数据契约必须完整。 |
| 待办 | 不再分「待确认」与「待处理」。同一 tab 按问题分成**新候选 / 需要复核 / 整理建议**，每条只属于一组；每行右侧必须有可直接执行的动作。 |
| 策略的位置 | 记忆的工作区级策略（写入、召回、保留）只放在**设置 → 工作区 → 记忆**。记忆主面只管理内容，不再复制任何旋钮。 |
| 自动入库 | Provenance Gate 完成前必须禁用；开放后也只允许低风险 `lesson` 自动进入知识库，不能自动升为 `confirmed`。 |
| 召回试算 | 设置页必须能**当场预览**：输入任务描述，列出会带入与会过滤的记忆、原因和 token 占用。预览读取未保存草稿，但不写记忆和使用记录。 |
| 不可配置边界 | `claimed` 不进入验证上下文、`confirmed` 只由人设置、用户偏好只能由用户确认、遗忘必须先退役并留墓碑。它们是只读规则，不做开关。 |
| 知识图谱 | 以选中知识为锚点，默认显示一跳，可切换两跳；支持按范围、生命周期与关系类型筛选，并提供节点检索、节点详情、使用记录及关系明细。关系明细必须写清来源、类型、目标、状态、依据和可执行动作。 |
| 系统诊断 | 进程、数据库、事件流、记忆写入、索引关系、召回降级、磁盘快照、数据与文件位置、日志及诊断包统一进入**设置 → 应用 → 系统诊断**；只给状态、证据和修复动作，不放配置旋钮。 |
| 「写入被拒绝」为 0 | 不一定是好事——它也可能意味着写入这条路根本没被走过。必须和「入库」一起看。 |
| 检索降级 | 语义那一路挂了退回纯关键词并**标成降级**，不静默降级。关键词是全管线唯一不经过模型的召回路，永远保留。 |
| 效用四层 | 被展示 ≠ 被引用 ≠ 被采纳 ≠ 帮到了，**不可互相代证**。统一进入**统计 → 记忆效用**；最后一层给可下钻的证据链，不用前三层加权凑分数。 |
| 关系图 | 以锚点为中心，默认一跳并可按需展开两跳，不铺全局节点云。建边时统一解析目标，指不到的关系建不出来（不出现悬空边）。 |
| 冲突边 | **不自动消解**，留哪条是人的判断。被替代的一方转退役并记 `superseded_by`，冲突边随之变成替代边。 |

## 自动化

| 元素 | 实现约束 |
|---|---|
| 执行去向 | 自动化建立的**永远是普通任务**，不形成第二套任务体系。不提供「仅运行、不建任务」开关——后台静默跑会形成第二套不可验收的结果。（V3.40 曾加过三档产出，V3.41 撤回：真要解决「没发现也建任务」的噪音，应由规则自己判断有没有发现，而不是让人先选一个模式。） |
| 任务内容 | 就是**一份 Markdown 文本**，人可以直接改。只读态渲染，编辑态给源码。人写一句话 → 模型整理一版 → 人确认一次，之后**每次触发读同一版，不重新生成**——每次触发都让模型重写，规则会静默漂移。**排在概览最后**：它最长，排前面会把其余几块顶到屏幕外。 |
| 详情结构 | 标题 → **一句简要描述** → **一行只读 meta**（项目 · 近 30 天运行概况 · 最近一次结果）。meta 只放**别处没说过**的语境事实：标题模板、工作流、权限都不重复。主区 tab 叫**属性**：`[触发条件 ｜ 执行组合]` 并排 + `任务内容` 全宽在下。 |
| 可编辑范围 | **触发条件 / 执行组合 / 任务内容三块可编辑**，其余全部只读。任务壳跟着项目走，权限跟着项目走。 |
| 时间表 | **不出现 cron 表达式**，只读写「每周 · 周一 09:00」，编辑用 `频率 + 具体日 + 时间 + 时区` 的结构化选择器，配一行**下次运行预览**（绝对时间 + 相对时长）。 |
| 协议名 | `HMAC-SHA256` / `Idempotency-Key` / `issues.opened` 这类不进界面——使用者要判断的是「验不验签」「重复投递去不去重」「收不收编辑事件」。 |
| 执行组合 | 拆成**模型**与**思考深度**两个下拉，不做成一个组合下拉——深度是「每次派工可调、不烧进配置」的那一维，合成一个下拉时换深度要在十几条里重找同一个模型。模型那一栏写 `模型 · adapter 版本`。下面给**现算的组合预览**。 |
| 深度可选范围 | **跟着模型走**：模型不支持的深度置灰，并把当前值回落到它支持的最高档。不可选比选了再报错好。 |
| 可派工范围 | 只列当前可派工的组合；被额度或登录态挡住的不出现在选项里。 |
| 权限 | 自动化**不单独设权限**，跟项目走，只在卡片上只读显示一行摘要。 |
| 启用状态 | 做成**开关**，不是一个状态词。关掉时文字变「已暂停」并说明后果：正在跑的不受影响，到点不再触发。 |
| 权限 | 只能**收紧到项目已授予的范围之内**，不能超出。缺权限时记「未触发 · 缺授权」并通知，**不自行降级去跑**。 |
| Webhook 入口 | 入口检查（验签 / 去重 / 事件过滤）与准入检查（额度 / 运行时）**分开记**：前者停在入口，不消耗额度也不产生 Run。 |
| 不可信输入 | 投递内容来自公网，**只作为任务上下文，不参与权限判断**——正文里写「请帮我推送到 main」不会让规则拿到 push 权限。 |
| 运行记录 | `未触发`（准入前挡下）、`失败`（已经执行）、`已暂停` 三者分开。**「未触发」不属于故障**，但使用者需要知道当日实际未执行。 |
| 手动重跑 | 新增一条运行记录并建立新任务，**不改写旧记录**。基础设施重试属于同一次 Run 的 Attempt，不伪装成一次新的规则触发。 |
| 投递重放 | 签名失败、排队中或已被过滤的投递**不能重放**。重放不参与原幂等键去重，但必须保留 `replayed_from` 来源。 |

## 项目

| 元素 | 实现约束 |
|---|---|
| 设置 tab | 与设置面使用同一套表单和数据列表形态，固定为 `项目信息 · 代码仓 · 文件访问 · 项目管理` 四个分区。名称与说明在项目内维护；归档后保留已有任务、记忆和执行记录。 |
| 项目记忆 tab | 它是记忆 · 知识库按当前项目作用域生成的筛选视图，不是独立存储。表格与知识库统一使用 `可信等级 · 记忆内容 · 记忆类型 · 作用域 · 生命周期 · 验证记录 · 最近召回 · 引用 / 采纳 · 详情`；支持按关键词、可信等级、记忆类型和生命周期组合筛选。行级详情会定位到知识库中的同一条记忆，完整管理入口仍是记忆 · 知识库。 |
| Skills tab | 项目不建立独立工作流对象，直接引用能力面的 Skills。字段固定为 `Skill 名称 · 能力要求 · 来源 · 项目使用方式 · 更新时间 · 操作`；这里只设置项目默认项与进入统一详情，不复制步骤和完成要求。 |
| 项目代码仓 | 复用设置 · 代码仓的数据模型和列表样式，显示当前项目引用的仓库子集。一个项目只能有一个可写主目录；参考仓库为 0..N 个只读引用。仓库路径、远端和机器授权仍统一在设置 · 代码仓维护。 |
| 文件访问 | 项目只配置读取范围和写入范围；主目录可读写、参考仓库只读。网络和 `git push` 不作为项目配置项。任务派工时可以进一步限制文件范围。 |
| 配置去重 | 默认 Skill 只在项目 · Skills 中设置；通知、记忆、标签、执行组合和机器路径均使用各自既有入口。网络与 `git push` 不设置项目级开关，按运行环境的实际可用能力执行。 |

## 设置

| 元素 | 实现约束 |
|---|---|
| 一级目录 | **只放类别**，不放实体实例与动作；每一项都要有真实页面，**不留点了只弹一句话的死路**；不出现状态灯。 |
| 分组 | 按**作用域**分（应用 / 工作区），不按主题分——作用域回答「我改这个会影响谁」。 |
| 个人资料 | 显示名与头像只影响界面。**提交身份不在这里**——见下面「代码仓 · 提交身份」。 |
| 界面语言 | 短期不做多语言，界面上暂不提供这个开关。做的时候有一条硬规则：**界面语言不改派给 agent 的提示语言**，否则会得到「换个界面语言，结论就变了」。 |
| 通知渠道 | 目前只做应用内与系统通知。全部可关闭，但**全关时必须警告**：「等待指派」这类状态将只能靠使用者自己回来查看。免打扰时段内只记录不推送，结束后合并成一条摘要。 |
| 通知事件 | 每一条都对应界面上**已经存在的状态**，不新造提醒。**「未触发 · 额度不足」必须通知**（那一天什么都没发生，界面上没有新东西会引起注意）。通知**不改变任何状态**，也不是第二套操作路径。 |
| 任务前缀 | 改一次要重命名全部已有任务；已写进 commit 与证据的旧编号**不会跟着变**，只保留一条别名记录。所以它是要确认的操作。 |
| 标签 | 定义在工作区，所有项目共用一份。**不参与派工判断**——做成路由信号会让两套判断互相污染。被自动化规则引用的**删不掉**，需先改规则。「90 天未用」建议合并，所以**合并功能必须真的存在**。 |
| 代码仓 | 主代码目录可写（带写锁、git 分支、执行 cwd）；参考仓库**只读、什么都不带**。 |
| 代码仓 · 添加 | **只有一个入口**，不让使用者先选「本地还是远端」：填本地路径或仓库地址都可以，保存时按内容自动判断。本地目录会**自动读一次 git 配置**——识别到 remote 就把远端一并绑上，识别不到就按纯本地目录处理并标明「拿不到 PR 与 issue」。**不要求手填名称**，从仓库名或目录名读出来。 |
| 代码仓 · 路径授权 | **按真实路径给**：软链、junction 与 worktree 先解析到真身，否则「授权 A、经由软链写到 B」就是一条绕过。一台机器一行，可设读写 / 只读 / 不授权。某台机器上没有这份代码时，涉及它的任务**不派到那台机器**。闲置 90 天标出但**不自动撤销**；撤销授权与删除项目是两件事。 |
| 代码仓 · 提交身份 | **读执行机器上的 `git config user.name / user.email`，不另存一份**——agent 产生的 commit 用的就是那台机器上使用者自己的 git 身份。界面上只说明它从哪来，不提供第二个输入口。 |
| 插件 · 配置 | 需要参数的插件（API Key、抓取上限、结果是否落盘）走**配置弹窗**，配置项存在本机数据目录里、随插件一起卸载。弹窗同时列出它提供了什么、哪一项未生效。 |
| 插件重名 | **重名直接拒绝导入**，不进入准入流程。冲突不该先被造出来、再让使用者去选一个。 |
| 插件 | **停用 ≠ 卸载**：停用是注册/注销级的，历史执行记录仍显示当时的版本；卸载才把目录从本机拿掉。「装了一半」必须显示出来并列出是哪一项。同名冲突由使用者选。**停用一个插件不改写历史**。 |
| 插件风险 | **本机没有沙箱**：插件与主程序同权运行，能读到数据目录里的明文密钥。所以准入是逐项确认，不是一个开关。 |
| 导出 | 默认**不含项目事实**（Memory 原始内容、Evidence、本机绝对路径），导出弹窗逐条列出剥离了什么。 |
| 数据目录 | 数据库文件**没有加密**，`agent_configs.api_key` 是明文列。这条警告必须跟着系统诊断里的数据目录一起出现，关于页不复制。 |
| 备份 | **没有恢复入口的备份不成立。** 当前只给快照位置，不承诺界面上的一键恢复——界面不承诺它没有的东西。 |
| 删除弹窗 | 三块缺一不可：**这会动到什么**（现算影响面）· **这不会动到什么**（历史执行记录、证据链、验收结论一律不动）· **退路**（最近一次快照几点、在哪）。**不做「输入名称以确认」**。被引用时不给删，把人送去解引用。 |
| 引用计数 | 常驻在对象上，不等到点删除才第一次告诉使用者。 |

## 全局

| 约束 |
|---|
| **界面只写「会发生什么」与「该怎么做」。** 设计论证、参考项目对比、文档坐标（ADR 编号、章节号）、写给设计者的备注一律不进界面——它们在 `design.md` 与这份文档里。 |
| **说明段落不超过 150 字，整站说明性文字不超过 4500 字。** 超了说明约束又开始往界面上爬，把它挪回这份文档。 |
| **不发明名词**：一个名词如果只能靠它旁边那段解释才立得住，它就不该存在。 |
| **不列没有页的行。** demo 死路比缺项更伤——它承诺了一个不存在的东西。 |
| **占位动作分两类，属性不同，不许混用。** `data-demo="<按下之后会发生什么>"`＝**交互已经定案**，原型只是用一句话代替真实结果，实现时照着这句话做；文案必须写结果，「打开 X 选择器」这类只描述控件动作的不算数。`data-unbuilt="<为什么现在没有>"`＝**这条还没定案**，界面上置灰但在场，原因写在按钮上。**判据：实现方看一眼就该知道该照做，还是该先来问。**四百多个占位混在一个属性里时，这个判断做不出来。 |
| **不能做的事要写明为什么不能**，并给出替代路径（置灰 + 一句原因，不是隐藏）。 |
| **弹层、数据表、页签只有一套语义与键盘模型**，实现时由一处统一施加，不逐个页面手写：弹层 `role="dialog" + aria-modal + 可访问标题`，焦点打开时进入、Tab 不外泄、Esc 关闭、关闭后归还给触发它的控件；数据表的行子元素报 `columnheader / cell`，横跨整行的补充说明与展开区不算单元格；页签 `aria-selected` 跟随选中态，一组只留一个 tab stop，方向键与 Home/End 可切。**逐处手写必然漏**——41 张表曾经一个 `cell` 都没有。 |
| **可访问性必须是门禁的一部分**，不能只靠人眼。`browser-check.mjs` 里键盘与语义断言与结构断言同级；新增任何一种弹层 / 表 / 页签形态时同步扩展，并做一次变异验证确认门禁会红。 |
