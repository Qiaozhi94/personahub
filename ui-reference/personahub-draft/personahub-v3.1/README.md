## V3.27 修版

按**增删改查**把设置里的每个对象核了一遍。判据：一个对象在界面上出现，它的增 / 查 / 改 / 删就都要有落点；某一格确实不该有，也要写明为什么。

**漏得最狠的是 adapter 配置。** 设计文档反复引用「删除一份配置会让依赖它的执行组合从派工清单消失，但历史 Run 保留当时的组合名」——而界面上**根本没有触发它的地方**；同样，「两者都不会把配置自动停用，**停用是你的决定**」这句话，承诺了一个不存在的动作。

补齐六处：

| 对象 | 补了什么 |
|---|---|
| adapter 配置 | 停用 / 启用、编辑、删除 |
| adapter | 从这台机器移除 |
| 机器 | 重新配对、移除这台机器 |
| 标签 | 重命名 / 合并到… / 删除（被规则引用时删不掉） |
| 能力包 · 插件 | 卸载（与「停用」分开） |
| 任务前缀 · 时区 · 外部编辑器 | 确认弹窗 / 可编辑入口 |

### 三条从 clowder 与 multica 借来的做法

1. **先给可逆的那一档。** multica 的智能体详情顶部常驻「已归档 · 无法被分配或提及」加一个「恢复」——归档是可逆的软删除。落到本产品：配置此前只有删除，而删除会连明文 key 一起带走；**连不上、key 过期这类，要的是先停掉别再派工，不是删**。
2. **引用计数常驻在对象上。** multica 的 skill 详情写着「被 0 个智能体使用」「还未分配给任何智能体」。所以配置卡上常驻「被 N 个执行组合引用 · N 条自动化规则用到」——**删除弹窗因此只是确认你已经看见的东西，不是第一次告诉你**。
3. **写明「你能对它做什么、改动何时生效」。** multica skill 详情有一个「权限」区：「你可以编辑和删除这个 skill。修改在智能体下次运行时生效。」本产品有正在跑的进程，这件事更不能不说：**改动从下一次派工起生效**，正在跑的不受影响（换配置要冷启动一个新进程，ADR 0009）。

clowder 那边确认了一个已有做法是对的：成员列表 Owner 那行直接写「**只能编辑，不能新增或删除**」——不能删的东西要在行上写明为什么，同本设计的「内置来源不可停用」。

### 删除弹窗：六处共用一个形态

三块，缺一不可：**这会动到什么**（现算的影响面）· **这不会动到什么**（历史 Run、证据链、验收结论一律不动）· **退路**（每日快照最近一次几点、从哪恢复、代价是什么）。

第二块**不是安慰，是必需项**——不确定删了会不会把历史一起带走时，真实反应是不删，于是界面上永远堆着一批不敢动的东西。

**不做「输入名称以确认」。** 两个参考项目都没有这道闸，而本产品每天有快照，真正的安全网是它。到处都要抄一遍名字，人会条件反射地照抄，那道闸就不再拦住任何东西。

**被引用时不给删。** 标签被自动化规则引用时，主按钮变成「先去改这些规则」而不是「删除」。

### 用词

全稿与原型里的「**弹层**」统一改成「**弹窗**」（45 处），它更常用。

## V3.26 修版

**adapter 表提到「运行中」上面。** 两条理由：**master 与 detail 的起点要对齐**——运行中排在前面时，adapter 表被顶到半屏以下，而点第三行弹出的右框却从顶部开始，视线要跳一次；**稳定的内容不该被易变的内容顶着走**——运行中的行数随进程增减，adapter 表是这一页的主体却会跟着上下漂。

**右框取消了框内的「配置 / 诊断」两个 tab。** 判据用的是 §3.2 里已经写过的那条：**tab 之间是并列的几组东西，不是一棵树**——而这一框装的是「同一个 adapter 的一串事实」，是线性的；何况诊断那一侧只有两行，撑不起一个 tab。改成四块固定顺序的分区：**状态 · 配置 · 工具 · 做不到什么**。

**属性一律收进它所属的那张配置卡。** 可用模型与深度、时限额与周限额、并发、项目可用性，全都是 `AdapterConfig` 的字段（ADR 0012 第 2 条）。V3.24 把它们摆在配置卡外面，结果 OpenCode 那两份只能靠 `coding-plan` / `official-api` 前缀硬拼在一起——**那是个补丁，和「删掉的五样」第一条批过的「模型表额度列只能靠『同池』打补丁」是同一类错误**。收进卡里之后归属由结构表达，连「额度挂在配置上」这句说明都不再需要。

**论证从界面撤回文档。** V3.24 的右框里塞了大段设计理由（为什么不折算次数、为什么额度挂在配置上、什么叫债务展览馆）。那些属于 `docs/design.md`。界面只留使用者要用的事实，**唯一的例外是解释一处缺席**——「登录态不代管，所以这里没有输入框」这类，因为使用者会在那儿找一个不存在的字段。

同一条标准也用在了左栏：adapter 表下面那段（三行 ADR 引用）收成两句怎么读这张表；运行中下面那段收成三句可操作的；远程机器那块留下后果与「远程执行在 v0.7」，删掉元评论。**验收里加了一条断言直接查这个**——整个机器 tab 内不得出现「判据 / 债务展览馆 / 打补丁 / 中心问题的另一半」这类词。

## V3.25 修版

> 一处改动，但牵动四个地方。

**额度不再折算成「还能派几次」。** 界面上原来写的是「剩 214 次 low ／ 42 次 high」，那是拿一个固定的深度换算系数（`high ≈ 5 次 low`）从剩余百分比反推出来的整数。使用者说不需要它：「我大概能评估出来，只需要给我时限额和周限额即可。」

**采纳的理由不是「用户要的」，而是它本来就错。** 真实消耗按任务差异极大——同样一次 high，读三个文件和跑一轮全量验证不是一个量级；**反推出的整数带着一种它没有的精确感**，而使用者自己对「还能干几件事」的估计反而更准，因为他知道下一件事有多大。这与 ADR 0017 自己的原则同源：那份决策引用 clowder 的原话要求订阅等价成本 *never present them as actual billing*，而**把折算值呈现成计数，和把折算成本呈现成账单，是同一类错误**。

改成每份 adapter 配置报两行上游自己给的口径：

| | |
| --- | --- |
| **时限额** | 滚动窗口（例如 5 小时）的已用百分比 + 重置时间 |
| **周限额** | 本周已用百分比 + 重置时间 |

三条约束：**取更紧的那一个**作判断；**重置时间必须给**——只有百分比时「等一会儿就好了」判断不出来，而它决定这一刻是该等还是该换一份配置；走 API Key 的配置两个都没有，写「不设上限 · 按 token 计费」，成本归统计面。

**跟着改的四处**：派工弹窗顶部那句额度说明、模型行上的额度标记、深度滑条下面的估算行（从「约够 7 次调用」改成报两个口径并指出哪个更紧）、额度不足挡下派工时给的理由（不再说「不足以完成一次 high（需 5 次）」，改成说窗口用了多少、几时重置）。告警阈值 20% / 10% 的口径也随之变成「两者中更紧的那一个的剩余量」。

**深度换算系数从界面上全部消失**，包括解释文字里——把它印出来只会让人拿它当真。

**动了一份 ADR。** ADR 0017 第 2 节那格写着「额度＝当前还可派出几次 high」，与这一改直接冲突。按 ADR 0006 立的规矩（「若调整幅度大到改变本决策的结论，通过补充或 superseding ADR 记录，而不是直接在 design.md 里悄悄偏离且不留痕迹」），在 ADR 0017 里就地加了一段 **2026-09-04 补记**：结论（额度属 Runtime、不进统计模块、三个口径永不相加）一条没动，改的只是额度在界面上长什么样。

## V3.24 修版

> 本段只覆盖设置 · 运行时。

**机器成了一层，因为它是 adapter 自己答不了的那一层。** `runtime_id` 早就是 `AdapterConfig` 与身份快照上的字段（ADR 0015 第 1、2 条，v0.3–v0.6 恒为 `local`，远程执行在 v0.7），界面现在按目标形态搭：**一台机器一个 tab，每接一台远程机器就多一个 tab**。

不能省这一层的理由是一个具体失败模式：**机器掉线时，它上面所有 adapter 都派不了工，而每个 adapter 自己的检查仍然显示「上次检查通过」**——那是上一次能连上时的结果。状态因此分两级报：先机器，再 adapter。multica 的运行时页同样按电脑分组（ADR 0015 的对比表已记下）；clowder 只在 API server 那台机器上 spawn，所以它没有这一层。

**tab 内三块，顺序即优先级**：这台机器（地址 / daemon / 在线 / 时钟偏移）→ 运行中（这台机器上正在跑什么，可以单独停）→ adapter 表（`状态 · adapter · 版本 · 配置 · 可用组合 · 现在挡着什么`）。**点 adapter 那一行弹右框**看详情，右框内仍是配置 / 诊断两个 tab。

**V3.17 的「主面永远是某一个 adapter 的详情」被替换了。** 那条防的是「同一块地方要维护『选全部』与『选一个』两套内容」；现在列表与详情是两块地方、各有各的职责，那个失败模式不成立——换上来的是 §3.2.3 那条「列表回答挑哪一条，详情回答这一条是什么」。「没有『全部』总览行」继续有效。

**两条跟着机器层走的调整**：「运行中」从「本机维度」归到 tab 内（它本来就是 per-机器 的事实）；**额度告警阈值再提一层到 `sp-bar`**——它跨机器生效，而要改一条全局策略不该先被迫选中某一个具体对象。这已经是它第三次搬家，每次都是同一条理由。

**逐项审视，删掉五样**：

| 删掉的 | 为什么 |
|---|---|
| 模型表的**额度**列 | 额度按配置分池，给每个模型开一列最后只能靠「同池」两个字打补丁——**一个需要补丁词才能自圆其说的列，本身就是错的** |
| 模型表的**状态**列 | 三行恒为「可用」；不可用的模型根本不会进「可用模型」清单 |
| 额度池表的**配置 / 认证**两列 | 单配置视图里恒等于上面那份配置已经说过的 |
| 工具表的**缺了会怎样**列 | 一整列只有一行有值——**只有一行有值的列应该是行内说明，不是一列** |
| 诊断的**近 30 天派工计数**与**登录态到期** | 前者是回顾，口径归统计面（运行时是前瞻，同屏并列会出现两个时间口径）；排障要的是「最近那一次失败是什么、点得进去」。后者在配置里已经写过一遍 |

**同时补回来一条**：「登录态不代管」不能随页首一起删——它回答的是**「为什么这里没有输入框」**，所以贴到 OAuth 那两份配置旁边写。

**执行位置不进执行组合名。** 组合仍是 `adapter × 配置 × 模型 × 深度`；位置进身份快照的 `runtime_id`。否则同一个组合在两台机器上会变成两个名字，现算表现也被切成两半。**同名 adapter 在两台机器上是两份东西**（两份安装、两份登录态、两个额度池），列表不做跨机器合并——合并之后「去重新登录」就不知道该在哪台机器上执行了。

**留了一个没答的问题**（§7.7）：接上第二台机器之后，「同一个模型跑在两台机器上算不算同源」会立刻冒出来。ADR 0015 明确把这个语义留到 v0.7，所以这一版界面**不给它任何暗示**——机器 tab 只表达「在哪执行」，不参与独立性判定的措辞。

## V3.23 修版

> 本段只覆盖设置面与它牵动的两处（能力面的工作流合并、派工弹窗的「本次生效组合」）。

**「乱」有一个可判定的成因：一个导航列表同时装了三种东西。** 改版前设置的一级目录八行里，既有**类别**（任务前缀与标签、数据与备份），又有**实体实例**（Codex CLI / Claude Code / OpenCode），还有**动作**（＋添加 adapter、首次设置向导）。后果有三条：列表长度不再由设计决定而由「装了几个 CLI」决定；点击契约不一致（多数行换一页，adapter 行换页并选中）；**风险最高的流程长得最便宜**——「添加 adapter」是 T2 代码准入，却和「任务前缀与标签」视觉重量一样。

**运行时收成一行，adapter 回到 pane 内左框。** §3.5.4「这一组有左框」那条论证一个字没改——那个左框本来就是 pane 内部的，V3.21 只是把它焊到了一级目录上。同时补上一条硬规则：**一级目录不列没有页的行**，改版前有三行是点了只弹一句话的死路，而 demo 死路比缺项更伤，它承诺了一个不存在的东西。

**补齐五页**：偏好设置（外观 / 时区 / 外部编辑器 / 语言）、通知、代码目录授权、健康诊断、关于。其中两页值得单说：

- **通知不是可选项。** P0 是全手动派工，一步跑完就停在「等待你的指派」——没有通知，这个状态只能靠使用者自己想起来回来看。结构照 clowder 的通知页（渠道 + 事件偏好 + 诊断），七类事件每一条都对应一个界面上已经存在的状态；只做应用内与系统通知两个渠道，IM 与移动推送解决的是多人场景。
- **代码目录授权不是「代码目录权限」。** 后者与项目里的「能力边界」语义重叠。全局层只管「这台机器上哪些真实路径被授权过、谁在用、还要不要留着」，四档开关仍然写在项目上。

**三处自我否定，记下来免得再犯**：①「权限档」是「能力边界」的第二个名字，正名不新建页；②「执行策略」是为凑整而发明的容器，逐项归位后不需要存在（并发→adapter 配置，照 multica 把并发挂在执行体上；去重→已在自动化准入检查；时区→偏好设置；额度阈值→运行时页首）；③「运维监控」不整块搬——clowder 那页九个 tab 里，七个在本项目已有归属，真正缺的只有「后台会话」，它变成运行时页首的「运行中」。

**MCP 不单开一页。** 当前模型里 MCP 只有一个来源（能力包声明），没有「自己装第三方 server」这个用法——为一个还不存在的用法建页面就是债务展览馆。但它必须有落点，因为工具静默缺席会让两次执行看起来一样、结论却不同：落点是每个 adapter 配置里的「工具」表，和「本次生效组合」。

**工作流模板并进编组。** 改版前项目面的 Coding / Research / Docs 和能力面的「代码实现 + 独立验证」「调研 + 交叉核对」是同一批东西的两个副本。两个参考项目都没有独立的工作流对象——流程就写在 skill 里。合并时切一刀：步骤与完成要求归 skill，底座硬规则留核心层且**只能加严不能放宽**，「哪条是默认」归项目设置（照 clowder 的「全局默认 Mount Rules，项目可覆盖」）。

**补建了 §3.2.7「本次生效组合」。** 它此前只写在 `docs/design.md` 里，原型中一个字都没有，而同一段承诺的另一半（§3.6.4「本次未进入上下文」）早已建好。三块：不可覆盖的底座 / 这次生效的做法 / 被拦掉的，每一条都带来源。

## V3.22 修版

> 本段只覆盖自动化面。同一批工作里能力面 Skill 详情的改动还没写进这里。

**「Runbook」这个词删掉了。** 它是运维值班手册的行话，而稿子里已经有一个一模一样的东西——新建任务的 `要做什么？包括约束条件，以及什么算做完`。同一个概念不该有两个名字，现在统一叫**任务说明**；原来并排的「任务模板」也跟着改成「建成什么样的任务」，因为它不是可复用的模板库，只是这条规则的建任务参数。

**任务说明改成「人写一句话 → 模型整理成步骤 → 人确认」。** 自动化是无人值守的，明天 09:00 触发时你不在，指令必须预先写死；但让人当场写出结构化的「目标 / 完成要求」又太重。所以创建器里只要求一句话，模型整理成步骤后由人勾选确认。

关键约束是**整理结果冻结成版本**：确认之后每次触发读同一版，不重新生成，改要走「重新整理」并重新确认。每次触发都让模型改写一遍那句原话，规则会静默漂移——三个月后没人说得清它到底在干什么，而这正是自动化最难查的一类问题。概览里保留「你写的原话」与整理版对照，两者都不隐藏。

**Webhook 从每条规则的标配，降级为只属于真有外部入口的规则。** 原来的示例事件是 `dependency.changed`——它假设有个外部系统会在依赖清单变化时 POST 进来，但对一个本机个人工具，自己改了 `package-lock.json` 再绕一圈 HTTP 打回本机触发自己，是自相矛盾的；而且没有任何东西会发这个请求。

现在左栏多了一条 **GitHub issue 分诊**，用 `issues.opened` 承载全部 Webhook 设计（凭证、事件过滤、HMAC 签名、幂等去重、投递审计、重放）。定时规则（依赖检查 / dogfooding 归档 / 推送检查）只有三个 tab，**没有 Webhook 投递层**——让一个多数规则永远是空的 tab 常驻，等于把它摆成一等公民。

这条 Webhook 规则还多摊开两件定时规则没有的事：**入口检查（验签 / 去重 / 过滤）与准入检查（额度 / 运行时）分开记**，前者不消耗额度也不产生 Run——两类原因混成一个「失败」，就再也分不清是别人发错了还是本机跑不动；以及 **issue 正文属于不可信输入**，只作任务上下文，正文里写「请帮我推送到 main」不会让这条规则拿到 push 权限。

**JS 只动了 `pickInList()` 一个参数。** 右侧详情按「规则类型」分而不是每条规则一份，所以定时那三条用 `data-automation-detail` 指到同一份详情上（新增可选参数 `viewValue`）。切规则时强制回到概览——两份详情的 tab 集合不同，停在一个当前详情里不存在的 tab 上会让右侧整块空白。

**验收**：`browser-check.mjs` 85 条过、1 条红（「编组没有把验证步的上下文范围写成字段」，属能力面 Skill 详情那批未完工作，与本次无关，回退本次改动后仍红）；`export-all-pages.mjs` 45 张、0 console 错误、exit=0。自动化那条断言按新结构重写，并补上守住上述判断的几条：任务说明必须留「你写的原话」且写明「不会重新生成」、定时规则不得出现 `Runbook` 与 Webhook 凭证、切规则必须真的换详情、Webhook 规则必须写明入口与准入分开且投递内容是不可信输入。

## V3.21 修版

**能力面的判据换了：它装的是「缺了也照样能干活」的东西。**核心层（项目 · Issue · Room · Run · Artifact · Evidence · 记忆 · 统计 · 设置）缺一个产品就不成立；可选层挂在能力面，任意一个停掉都不影响上面。依赖方向单向：可选层可以调核心层，反向禁止。

这条判据同时给出一条**可判定**的插件准入规则——RSS 订阅缺了照样建 Issue、拉 Room、派工、验收，所以它可以开 tab；adapter 缺了就派不了工，所以 adapter 永远在设置 · 运行时，不进能力面。

改了四处：

1. **「来源」tab 删掉。** 它是自己长出来的第三个 tab：核查后 clowder 的插件组装在 Settings UI（`docs/research/plugin-architecture-dsh-clowder.md` 第 3 节对比表），multica 全文没有插件系统。来源降为表格里一列可点标记，跳设置 · 插件——这正是 §3.2.1 自己写的「来源是治理维度，不是查找维度」。
2. **编组不再是独立类型。** 一条 Skill 填了 `steps` 就是编组（自动带 `#编组` tag），不填就是普通做法；三个 tab 收成**一张表 + tag 筛选**。两个类型会逼人在用熟之后「转换类型」，历史表现跟着断，反而离 ADR 0012 第 5 条要防的「编组积累成身份」更近。
3. **运行时并进设置，一级入口 9 → 8。** 原 §3.7 整体搬进设置的「运行时」组；到达它的主路径本来就是跳转（派工弹窗「结构性不具备」、成果面独立性卡），不是左栏点击。设置同时新增「插件」组——**装一个 CLI 和导入别人写的一套方法不是同一件事**：失败模式不同（起不了进程 / 装了一半），处理动作也不同（去终端敲命令 / 在界面上选一个候选）。分开还有一处白捡的安全收益：**凭据全在运行时组、插件挂载点全在能力面，两处不相交**。
4. **插件的 tab 是声明出来的，不是插件画的。** 新增能力面第二个 tab「订阅」作为演示：`rss-inbox@0.3` 在 manifest 里声明 `kind: table` 加列名加两个动作，宿主用自己的组件渲染。动作只能引用白名单（`host.library.archive` / `host.issue.createWithRoom`），因此「深入拆解」建出来的是普通任务，来源链自动完整——插件自己拼捷径就会绕开它。ADR 0014 的 P12 随之从 C 档改为「声明式 surface 开放（B）/ 插件提供渲染代码仍关闭（C）」。

**JS 只加了两个函数**：`applyPicks()`（一个按钮可以同时切面和切组——设置左栏的 adapter 条目正是 settings + runtime 两个 pick 同时生效）与 `setLibFilter()`（tag 筛选）。

**验收全绿**：`browser-check.mjs` 84 条全过、0 console 错误、exit=0；`export-all-pages.mjs` 44 张、0 console 错误、exit=0。新增 3 条断言（能力面是容器、Skills 一张表 + tag 筛选可用、插件 tab 由声明渲染且动作走白名单），改写 8 条（竖栏不再有 runtime 且必须是 8 项、设置面必须有运行时与插件两组、密钥仍在数据组等）。**顺手修掉两处与本次无关的既有失配**：导出脚本的哨兵张数写着 38 而实际早已是 42；`data-settings-pick="data"` 在左栏和正文各有一处，断言未限定 `.sp-list` 会撞 strict mode。

## V3.19 修版

**轨迹详情：右侧详情栏 → 点哪行就在哪行下面展开**（形态照 deepseek-harness 的 trajectory）。

原来选中一行，内容出现在右边那条 340px 的详情栏里。问题是轨迹本身多数时候就是会话的副栏（420px），副栏里再切一栏就只剩两条窄缝——所以副栏尺寸下详情栏是直接 `display:none` 的，**会话面里点行等于没有反应**，详情只有放大成全宽复盘时才够得着。现在详情长在行下面：副栏、放大态、窄屏都是同一套交互，读的时候上一行发生了什么也始终留在视野里。

| 事件 | 头部定位 | tab 组 | 这一类真正要回答的 |
|---|---|---|---|
| SYSTEM | `Initial System Prompt` | System Prompt / Tools | 提示原文是什么、这次给了哪些工具 |
| USER | `Turn 1 · Message` | Summary / Preview / Raw / Source | 谁发的、原文、分块原样、请求元数据 |
| ASSISTANT | `Turn 1 · Step 1` | Summary / Preview / Raw | 来自哪个 Request、tokens 拆成 Reasoning/Content、思考与正文分块 |
| TOOL | `Turn 1 · Step 1` | Summary / Payload / Result / Schema / Timing | 入参、结果、这个工具的契约、实测耗时 |
| Request | `Turn 1 · Request #1` | Summary / Timing / Source | **DSH 没有这一类**：它把请求收在 ASSISTANT 的 Source 字段里，PersonaHub 把它单独成行（要标冷启动/续跑），字段沿用 DSH 的 Request Timing 那一组 |

诊断信息（`run_a3f2` / 原始 session 路径）跟着 DSH 的分层走：不再是详情栏底部那条固定脚注，而是 Request 的 **Source** 页；TOOL 的 Timing 页只写 Started / Duration / Timing source。脚注挂在栏底时看着像整段轨迹共用一条，实际它按调用不同。


## V3.15 修版

**运行时从设置里抽出来，成为一级工作面。** 结构判断见 `docs/design.md` §3.7，模型依据是 `docs/decisions/0012-object-model-simplification.md` 第 2 条。

起因是 ADR 0012 把执行组合从三元组改成 `adapter + 配置 + 模型 + 深度`，并把 adapter 拆成两层：**adapter 是一个 CLI 安装**（版本、能力位、原生记忆、执行位置），**配置是驱动它的一种方式**（base URL、认证、可用模型、额度、项目可用性）。拆完之后这一簇字段比设置面其余三组加起来还多，而它的访问频率是「派工失败时第一个去的地方」——和设置「低频、改完就走」不是一个节奏。

改了五处：

1. **新增 `data-surface-view="runtime"` 一面**，排在统计之后、设置之前。壳复用 `split-surface`（与自动化面、设置面同款），**没有新增一行 JS 逻辑**：左框走既有的 `pickInList()`、tab 走既有的 `setLocalTab()`，只在两个 group 数组里各加了一个 `"runtime"`。
2. **左框是 adapter 列表**，顶部一行「全部」总览。有实体就有列表——这是 §3.4 已经写下的规则（记忆面与能力面没有左框，是因为它们的 tab 是并列的三组东西，不是一棵树）。状态灯复用已有的 `.sp-item:has(> .signal)`，**灯旁必须有文字**，且 per-project 的可用性差异不进灯（灯是全局符号，说不了「这里可用、那里被停了」）。
3. **主面三个 tab**：能力（CLI 安装这一层的能力矩阵，不支持的格子写后果而不是画 ✗）、配置（执行组合全表 + 额度池 + 凭据）、诊断（每一行都带可执行动作）。
4. **设置面收敛为低频三组**（任务前缀与标签 / 数据 / 其他），原来的「Adapter 与执行组合」「模型与凭据」两块整体搬走。
5. **额度按 adapter 配置分池，不叫「账号」**。派工弹窗里逐模型标百分比的老 bug 一并修掉——claude 的 opus 与 sonnet 同属一份配置，不可能同时剩 62% 和 88%；现在每行标它属于哪个池。

**OpenCode 挂了两份配置**（`coding-plan` / `official-api`），这是四元组存在的那个真实场景：同一个 `deepseek-v4-pro` 两条路，一条吃套餐额度、一条按 token 真花钱，失败模式也不同（前者撞限流，后者不限流但烧钱）。合成一行会让历史表现被平均，那张表就不能再用来做判断了。

**防护条款写进了断言。** 运行时面不出现「设为默认 / 优先级 / 置顶 / 重命名」——判据是「改了它之后『派工时该选谁』的答案会不会变」。会变的就是偏好，偏好会让 adapter 长回 ADR 0012 取消掉的「AI 成员」。

**验收已跑。** 本机跑过 `browser-check.mjs`（**73 条全过、0 console 错误、exit=0**），确认结构可用。（当时还有一份截图导出脚本，每轮重刷三十多张 PNG 只是 diff 噪声；V3.26 起整条规则已删除，见「验收」一节。）

断言按新结构新增 3 条、改写 4 条：

- 新增：左框是 adapter 列表且灯旁必须有文字、能力矩阵横着比且不支持的格子写后果、同一模型两条路必须是两个执行组合。
- 改写：竖栏清单与顺序（运行时在统计之后、设置之前）、执行组合表改指运行时面且表头要能看出四个维度、额度与凭据两条从设置面搬到运行时面的配置 tab。
- 顺手修掉一条**与本次改动无关的既有断言 off-by-one**：「统计的任务行要跳回任务模块」取的是 `.dl-row` 的第一条，而第一条是合计行——合计行按设计不带页码、不随翻页变化，本来就不该跳转。改成 `.dl-row:not(.dl-total)`。

**这一条已由 V3.21 结清：** V3.13 的「来源」tab 最终没有实现，而是被删掉——已装能力包与插件归设置 · 插件组，来源在 Skills 表里只是一列可点标记。


## V3.12 修版

**「用量」改造成「统计」，额度搬回设置 · 运行时。** 结构决策见 `docs/decisions/0017-usage-accounting-and-stats-surface.md`。

起因是两个问题撞在一起。一是维度：multica 的 dashboard rollup 键是 `(date, workspace, agent, project, model)`，前端主表是智能体排行榜；clowder 聚合到猫。这两个维度成立是因为 agent / cat 是**可治理的对象**——看完排行榜能去关掉它。而 ADR 0012 已经把这一层取消了，照抄只会得到一张每行都没有对应动作的表。二是位置：原来的用量面通篇是「还能派几次」，可 ADR 0012 第 3 条明明把剩余额度定义成 Runtime 的字段——额度当时被放错了地方，而真正的 token 账本一直不存在。

改了五处：

1. **结构照记忆面，不照任务面。** 任务模块是「列表 → 单任务 tab → tab 下内容」，因为任务是实体；统计没有实体可列，选的不是哪一条而是**看哪一类问题**，所以进来就是 tab 页，没有左列表。只留两个 tab：用量、失败。
2. **主维度换成「去向」。** 详情表主维度为任务，第二维度为用途（实现 / 验证 / 返工重试 / 上下文重传）；模型与执行组合退为同一张表的第三、四个维度，定位是**单价基准**而非排行榜——更换组合会改变结果质量，这属于使用者的质量判断，不是降低成本的手段。四个维度共用一张表，通过卡内切换，不新开页面。
3. **实付与订阅等价分成两个数字。** 订阅账号跑掉的 token 不产生新支出、只消耗额度；API Key 账号不消耗额度、但每个 token 都是真钱。等价一行标注「非实际账单」——clowder 的价表注释里那句 *never present them as actual billing* 是付出代价后才写下的。组合表另加一列「计价来源」：adapter 自报为权威值，本地价表折算为估算值，合并为单一数字后将无法区分可信部分。
4. **年度热力图作为趋势卡的第三种形态**（逻辑与样式照 GitHub 贡献图）。不做成页首常驻横幅：那样它固定显示一年，而同屏 KPI 跟随周期筛选，页面上会并列两个时间口径的数字。形态由周期决定——近 7 天只有按天、近 30 天有按天 / 按周、近一年有按周 / 热力图并默认落在热力图；**不可用的形态置灰而不是隐藏**，藏起来等于替使用者决定他不需要它。
5. **详情表改分页**（每页 10 条，共 17 个任务），**合计行置顶**——紧贴表头、不带页码、不随翻页变化。原来的「其余 12 个任务」聚合行删掉：它存在的唯一理由是让各列能加到 KPI 上，但它点不动、不可下钻；合计行做同一件事，而且是正式数据表的常规做法。分页最容易翻掉的正是对账关系，置顶的好处是这个总量在翻页前就已经读到了，不必翻到底再找。不设「本页合计」——页内小计不回答任何问题，只是把表撑高。

   **Token 拆成缓存命中 / 未命中两列**：命中是从 prompt cache 读取、按折扣价计费的部分，未命中是本次真正处理的输入加上全部输出（输出永远不进缓存，所以算未命中），两列相加等于该行全部 token。四个维度的命中 / 未命中合计完全一致（79.0M / 52.6M），因为它们本来就是同一批 token 的四种切法。这一刀对应可调的旋钮：「验证」按 ADR 0009 冷启动，命中天然低；「上下文重传」命中率只有个位数，它的未命中量就是把上下文范围收窄能省下的上限。

   **同时修掉一个自造数据：**「返工 62%」原来挂在**状态**列里，而那一列其余的值全是任务状态——一个状态列里混进一个算出来的比例，读者无从核对它怎么来的（它当时确实也没有任何出处）。现在独立成「返工占比」列，口径写在表下：该任务 `step_kind='返工重试'` 的 token ÷ 该任务全部 token，17 行按 token 加权后是 17.98%，与「用途」维度写的 18% 对得上。
6. **术语统一为正式用词。** 分布卡定名为**详情**；「还能派」→「可派次数」、「上下文重发」→「上下文重传」、「权限被拒 / 超时 / adapter 报错」→「权限拒绝 / 执行超时 / adapter 错误」、「不是账单」→「非实际账单」、「跑了但失败」→「已执行但失败」。说明段落同步改写，去掉口语表述。
7. **额度整段搬到设置 · 运行时**（额度池按账号、深度折算、告警阈值），派工弹窗里「额度不够」的理由随之改指那里。统计面从此**全屏没有一个实时数字**。

**一处刻意的不一致。** 本项目一直守「未知不填 0、未计入单独成段」（V3.11 的轨迹条就是这么画的）。这一版**没有**为「adapter 没回报 usage」造视觉语言：没有 KPI、占比图里没有那一段、热力图上没有第六种记号。理由是三个 adapter 里已确认 Claude Code 会回报，后续只会适配更多 CLI，为一个可能不出现的情况造一整套记号，成本大于它防的问题。数据层仍然存 NULL 不存 0——那一列不要钱，而 0 与「没测到」一旦在写入时合并就再也分不开。

**数字是对得上账的。** 三个周期（7 / 30 / 365 天）的 KPI 与四张分布表由同一份 365 天的伪随机数据生成，每张表的每一列都能加到对应周期的 KPI 上，末行吸收舍入差。原型里数字对不上账，是评审第一个会抓的东西。

**验收：** `browser-check.mjs` **74/74 通过，零控制台错误**。断言按新结构改写并新增：统计面结构（无左列表 / 两个 tab / 筛选在 tab 行右侧 / 全屏无实时额度）、趋势卡的周期—形态门（热力图只在近一年可用且默认落在它）、明细回任务轨迹、详情表分页与置顶合计行（首页 10 行、合计不带页码且与 KPI 对得上）、失败页口径、额度落位。

## V3.10 修版

**记忆从「一张能看的清单」变成「能治理的库」。** V3.9 的记忆面已经有强度（stance）和 type，缺的是「这条现在还算不算数、错了怎么撤、库整体有没有烂掉」。按 ADR 0016 补三样，全部沿用 V3.9 的列表范式，不新增布局原语：

## V3.9 修版

**记忆与能力改用列表，不再用卡片。** 卡片的问题不是好不好看，是**管不动**：每张卡自带边框和内边距，同一个字段在不同卡里的位置对不齐，扫十几条就得逐张读；条目上百之后更没法比较。列表把字段压成对齐的列——横着能比、纵着能扫。

四个列表共用一个 `.data-list`（表头 + 行，列宽由 `--cols` 定）：

| | 列 |
|---|---|
| 记忆 · 待确认 | 强度 / 内容 / type / 来源 / 时间 / 操作 |
| 记忆 · 知识库 | 强度 / 内容 / type / 层级 / 来源 |
| 能力 · 编组 | 编组 / 步骤 / 上下文范围 / 工作流 / 状态 |
| 能力 · Skill | 强度 / 做法 / 工作流 / 触碰路径 / 命中 / 最近 / 操作 |

引文、警告、编组的理由放在次行（`grid-column: 2 / -1`），限宽 900px——列表可以铺满 1318，但要读的句子一行 100+ 字读不动。

**列宽必须写死。** 最后一列原来写 `auto`：表头是「操作」两个字、数据行是四个按钮，宽度不同，`1fr` 把差值吃掉，整行的列就和表头错开了 186px。列表的意义全在对齐，这一条有断言守着（逐列比对表头与数据行的 x）。

**两面的排版也彻底对齐了。** 之前差在两条只列了 `memory` / `projects` 的选择器上：能力面不在里面，还在吃 `.surface-content` 的默认值（`h1` 29px、`small` 9px 蓝色大写），于是 tab 行比记忆面低 15px，来回切整页往下掉一截。卡片则是 14/16 内边距对 12/14、编组标题 16px/700 对记忆 12px/600。现在断言逐项比对两面的 `header small` / `h1` / `.mem-tabs` 的字号、字重、颜色、y 坐标与高度。

另一个反复出现的坑一次性堵死了：在裸类名上写 `display` 会盖掉 `[hidden]`（`.trace-item` / `.baseline-gate` / `.claim-state` / `.project-manage` / `.project-pane.files` 都栽过，表现是切 tab 时上一个视图的内容还留在页面上）。现在有一条全局兜底 `[hidden] { display: none !important; }`，外加一条断言扫全站。

2. **顶栏去掉「均衡 / 阅读 / 协作」三档**。这三档是 V3.0 为「舞台 + Dock 两栏怎么分」设计的；Dock 已按 ADR 0012 取消，副栏也有自己的折叠开关，它就没有对应的东西可调了。
3. **项目面工具条改小图标**（照 multica 的 `size-7` 范式）：28×28 无边框方按钮，16px 线性图标，hover 才出背景，带 `aria-label` 与 `title`。
4. **目录树的状态标记统一靠右**，并改用 git 那套字母 `M / A / D`。跟在文件名后面时每行位置都不同，扫不出「哪些改过」。

1. **六个工作区面统一成「左框 + 右主体」**：左边是这一类东西的清单，右边是选中那一个的全部内容。此前各长各的样，每切一次都要重新找。
2. **独立会话成为一级对象**。不挂任何任务的讨论此前无处安放，硬塞在某个 Issue 下不合适。会话面分「独立会话」与「来自任务」两组；独立会话**不产生验收、不写记忆**，要落成结果走「转成任务」。
3. **项目面改成 GitHub 式**：左树右预览，点文件不跳走。代码带行号与增删标记，Markdown 直接渲染——方便连着看好几个文件。
4. **任务标识与元信息独立成第一行**，视图 tab 落到第二行。标题和 tab 挤在一行时标题被压成一小截，元信息只能塞进正文里重复七遍；拆开后元信息只有一份。
5. **标签收进下拉**。横排 chip 的问题是标签一多就折行，左栏高度跟着标签数量变。
6. **能力库改名「能力」，只留编组与 Skill**。「做法」是我自造的中文名，和 Skill 是同一个东西——统一叫 Skill，并给它能真正管理的位置：什么时候注入、来源与命中记录、启停。
7. **执行组合下沉到设置**，作为 adapter 的配置检查。它半年不变一次，却被放在天天要用的入口里；这张表是**检查结果**（装了哪个 adapter 就有哪些组合），不是配置项。
8. **竖栏分两组**：任务 / 会话 / 项目 / 自动化在上，记忆 / 能力 / 用量 / 设置沉到底部一排。用量单独成面而不是塞进设置——额度是天天要看的**约束**（今天还能派几次 high），不是配置项。
9. **新建任务弹窗重做**：居中，只问目标与归属（项目 / 工作流 / 标签），**不在这里挑执行组合**——建了任务不等于马上开跑，谁来做在任务里看着目标决定更准。输入框改漂浮态。
10. **设置里补「任务前缀与标签」**。任务编号一发出去就被 commit message、证据文件名、导出文件名引用，所以改前缀做成要确认的操作：会重命名全部已有任务，而写进 commit 和证据里的旧编号不跟着变，只留一条别名记录。标签明确**不参与派工判断**，只是筛任务和圈自动化规则范围的一层；被规则引用的标签删不掉。
11. **「成员选择器」改成「执行组合选择器」**。ADR 0012 取消了成员这一层，弹窗却还在按人选：名单来自能力库、行标题是「独立验证员」这种角色名。现在列的是设置里检查出的 7 个执行组合，名单不在弹窗里增删。同源判定跟着改为**看模型不看深度**——同一个模型换个深度再验一遍，验的还是它自己；额度不够跑完一次 high 也是不能选的理由之一，且理由指回用量面。
12. **「模型与凭据」照 clowder 的账户页做成真页面**（此前只是个 toast）。分两组：**CLI 登录态**由 CLI 自管，PersonaHub 只做只读检查、给终端命令，不代管 token——代管等于把三个 CLI 的凭据格式和过期策略全抄一遍；**API Key 账号**才是 PersonaHub 自己存的，单独成表。密钥落在明文 SQLite 列上，这条风险写在界面里而不是只写在文档里。

## V3.4 相对 V3.3 的七项变更

1. **左栏按组织维度分类，不再按状态分组**（照 clowder `ThreadSidebar`）。原来的「需要你处理 / 正在进行 / 最近完成」三组有个硬伤：状态天天在变，同一个任务今天在这组明天在那组，位置就记不住。换成**置顶 / 最近 / 项目 / 收藏**——位置由你决定，状态退回条目里的圆点。「项目会话」入口删除；**＋ 新建任务**提为顶部主按钮；任务可以打标签，分类 × 标签取交集。
2. **成果与资料合并为「资源」**，任务面从六视图收敛到五视图。拆成两个 tab 时，一个既被读过又被改过的文件会两边各出现一次；合成一个面、按**方向**分段（产出 / 输入）就没有这个问题。
3. **项目面换成 VS Code 式目录树**：左项目列表 + 右可折叠树，支持折叠、全部折叠、按名称过滤。原来把整个资源库平铺在项目卡片里，目录一多就放不下。
4. **记忆面拆成待确认 / 知识库两个 tab**（照 clowder `MemoryNav`）。待确认是 inbox，也是**唯一**能把知识升为 `confirmed` 的地方——写入触发器来自验收事件，但升级必须人点；知识库的核心是检索 + 按 stance 过滤。
5. **能力库改列执行组合**，不再是「AI 成员」卡片——ADR 0012 已经取消那一层。表格是 adapter × 模型 × 可用深度 × 额度；编组把每一步的**上下文范围**写成结构化字段，否则「独立验证」只是句口号。
6. **自动化每条规则摊开完整链路**：触发 → 在哪个项目 → 建任务并按哪个工作流 → 派给哪个执行组合 → **能力边界**。缺权限时规则停下来问，不会自己把权限降下来跑；执行历史把「未触发」和「跑了但失败」分开记。
7. **清掉四处残留的旧一级导航**。加竖栏时 `library` / `automation` / `settings` / `projects` 里的 `primary-nav` 没删干净，同一组入口在页面上出现了两次。
8. **轨迹概览换成三泳道**（照 harness 的 `TrajectoryTimeline`）：Chrome Network 风格的**输入 / 模型 / 工具**三条，记录按 kind 投影（`laneFor`：tool→2、message→1、其余→0）。此前那版逐调用一行的甘特图太占地方。模型条按 TTFT 切成两段；**计时未知画空心，绝不伪造 0ms**。（V3.11 已改为单条占比分段条，见下。）

## V3.3 相对 V3.2 的六项变更

1. **取消协作 Dock。** 会话降为任务面的一个视图；输入框常驻任务面底部，看着成果就能下指令，切视图保留草稿（`docs/v3.2-claim-evidence-proposal.md` §10）。
2. **任务面六视图**：概览 / 会话 / 验收 / 成果 / 轨迹 / 资料。tab 上的数字是**需要人工介入的件数**，不是内容总数；一件事只在它的处理位置计数。
3. **执行单位改为 `adapter + 模型 + 深度`**（如 `codex-gpt5.6-high`），取消「AI 成员」这一层。**选择分两步**：先从运行时的真实模型清单里挑 adapter × 模型，再用滑条独立调深度——不做固定组合，否则等于又造一遍刚取消的「成员」。档位由模型决定（只支持一档的模型滑条自动禁用），额度按深度折算成可用次数（ADR 0012 第 2 条）。
4. **上下文范围在派工时显式选**：全部 / 只给结果 / 只给目标。改回「全部」会触发降级提示——这次验证不算独立（ADR 0012 第 4 条）。
5. **项目照 multica 进左栏**，与任务并列；任务列表里的「项目 ▾」只作筛选，管理项目走 ▦ 入口。游离态任务归「未归类」。
6. **labels 代替父子 Issue**，「协作现场」退役为视图名（ADR 0012 第 8 条）。
7. **搜索只保留一处**：顶栏主搜索框接管左栏的任务筛选，左栏不再有第二个搜索入口。
8. **顶部只剩一行 chrome**：任务 tab 条取消，当前任务的标识并进视图行左侧；切任务回左栏点（左栏本来就常驻任务列表）。
9. **概览重设计为决策面**：只放别处答不了的四段——目标 / 等你决定什么 / 现在什么情况 / 下一步建议 + 一行简况指针。三卡与主张树全部归验收，两个视图零重叠。
10. **发给不再选会话**：在哪个任务下就发给该任务的活跃会话，选择器只剩执行组合。

## V3.2 相对 V3.1 的核心变更

可信度锚点从「证据」换成「主张 → 论证 → 证据」：三卡改为**已独立验证 / 有证据待验证 / 需要你处理**（三数之和等于主张总数），只用 `✓ ◐ ⚠` 三个符号，精确状态由每条主张的「结论」文字行承担——**同源验证拿不到绿勾**。证据用仓库里的天然标识，不新造编号体系。理论依据见 `docs/decisions/0010-claim-evidence-structure.md`。

## 相对 V2 的六个改动

1. **主舞台是成果面**，不再是「打开任意对象的通用画布」。Evidence Summary 从产出树下的三级页面升格为舞台的固定结构：系统记录 / 实际变化 / 验证独立性三卡 + 完成要求逐条挂依据 + 执行计划。
2. **舞台是主角**。V2 是画布 39% + Dock 39%（各 565px）谁都不是主角；V3 是舞台 55% + Dock 400px。
3. **左栏并成一栏**：48px 图标活动栏并入，一级入口带文字；四棵并列对象树收敛为**单一可折叠列表**（V3.0 曾用「任务 / 资源库」两 tab，V3.1 删除，见 design.md §4.5）。资源库退化为该列表下半部的三个分节（文档与素材 / 产出 / 知识），代码目录不常驻。
4. **删掉 IDE 隐喻**：编辑器标签页排、底部执行面板、底部状态栏。舞台单例，靠面包屑返回。
5. **Dock 概览 tab 拆解**：高频的「谁在做 / 第几步 / 卡在哪」上提为常驻两行；「详细执行计划」下沉到成果面。
6. **项目级会话**：没有选中任务时 Dock 显示不绑定任何任务的项目会话，可以直接问「这个项目现在什么情况」。

## 可点击范围

1. 左栏一级入口：两组八个——项目工作台 / 会话 / 项目 / 自动化，记忆 / 能力 / 统计 / 设置。
2. 任务列表：范围切换（当前项目 / 全部项目）、项目会话入口、任务与协作现场的父子层级、重命名 / 归档 / 删除菜单。
3. 资源库：文档与素材、产出、知识三组。
