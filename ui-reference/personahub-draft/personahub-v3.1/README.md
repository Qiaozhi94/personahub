# PersonaHub V3.2 · 用例承载可信度

V3 承接 V2 的对象模型、用户语言和浅色视觉语言。V3.1 把「一份随工作推进不断生长的任务成果」提为主舞台；**V3.2 换掉了可信度的锚点**——从「证据」换成「用例」。

> 起点是 V2 最终态蓝图（`personahub-draft/personahub-v2.1/`），V2 已修好的命名统一、Dock 跟随任务、状态页覆盖全部保留。

## V3.2 相对 V3.1 的六项变更

1. **可信度锚点换成用例。** 三张状态卡从「系统记录 / 实际变化 / 验证独立性」改为 **覆盖 / 对齐 / 时序**，对应可信链条 `设计文档 → 用例 → 执行结果` 的三个断点。原始命令与 diff 抽屉撤掉——判断改得对不对要打开全文，左栏资源树已能满足（`docs/design.md` §4.2.4）。
2. **用例必须先于实现固定。** 实现期间改过用例会在首屏亮红线，时序卡展开是可查的时间轴。这比「换个成员来验」有效，也不需要多养一个成员（依据见 `docs/decisions/0009-agent-session-lifecycle.md`）。
3. **执行计划改实现 / 验证双列，中间是上下文围栏。** 两列等宽等重；围栏右侧永远是一个新 session，看不到左侧的过程消息与自述。
4. **新增轨迹视图。** 任务 tab 内的「成果 | 轨迹」切换，不新开 tab。每个 Run 标出上下文血统（`⊘ 冷启动` / `⟳ 续跑自 Run #N`），原始 session 只在诊断层出现。
5. **砍掉 Dock 的「协作现场」tab。** 一个 Issue 一个协作现场，Room 作为可折叠段内嵌进任务会话流——Room 是组织单位，不是阅读单位。
6. **Dock 只有一个输入框 + 一个显式的「发给」选择器。** 顶部 chrome 从 9 行压到 2 行；任务名归舞台标题，Dock 只在收件人被固定到别的任务时才写它。左栏一级入口上移到搜索行（纯图标 + tooltip），设置留在底部。

## V3.1 相对 V3.0 的四项变更

1. **舞台顶部恢复标签页排，但只允许任务占位。** 一个 tab = 一个任务的成果面（§4.2.1）。
2. **左栏扁平为单一可折叠列表。** 删掉「任务 | 资源库」二级 tab（§4.1）。
3. **协作现场舞台改为「结构视图」。** 末段换成并行成员泳道，补上选人理由（§4.2.3）。
4. **七个任务态全部改为成果面。** 共用同一套结构，差异只在填充程度（§4.2.2）。

## 打开方式

双击 `index.html`，无需安装依赖或启动服务。

## 一句话结构

```text
左栏 248px   一级入口 + 任务列表 / 资源库
主舞台 ~55%  成果面：这件事现在做成什么样了、可不可信
右栏 400px   协作 Dock：谁在做、下一步交给谁
```

`docs/design.md` 是设计基线；实现可以调整像素与动效，但不得悄悄改变那里确定的对象归属、状态含义和操作影响范围。

## 相对 V2 的六个改动

1. **主舞台是成果面**，不再是「打开任意对象的通用画布」。Evidence Summary 从产出树下的三级页面升格为舞台的固定结构：系统记录 / 实际变化 / 验证独立性三卡 + 完成要求逐条挂依据 + 执行计划。
2. **舞台是主角**。V2 是画布 39% + Dock 39%（各 565px）谁都不是主角；V3 是舞台 55% + Dock 400px。
3. **左栏并成一栏**：48px 图标活动栏并入，一级入口带文字；四棵并列对象树收敛为「任务 / 资源库」两 tab。资源库只放用户资产（文档、产出、知识），代码目录不常驻。
4. **删掉 IDE 隐喻**：编辑器标签页排、底部执行面板、底部状态栏。舞台单例，靠面包屑返回。
5. **Dock 概览 tab 拆解**：高频的「谁在做 / 第几步 / 卡在哪」上提为常驻两行；「详细执行计划」下沉到成果面。
6. **项目级会话**：没有选中任务时 Dock 显示不绑定任何任务的项目会话，可以直接问「这个项目现在什么情况」。

## 可点击范围

1. 左栏一级入口：项目工作台、能力库、自动化、设置与诊断。
2. 任务列表：范围切换（当前项目 / 全部项目）、项目会话入口、任务与协作现场的父子层级、重命名 / 归档 / 删除菜单。
3. 资源库：文档与素材、产出、知识三组。
4. 成果面：三卡状态、成果本体（文件与阶段成果）、完成要求逐条追证据、执行计划；点文件进入全文视图后可返回任务。
5. 协作 Dock：任务会话 / 协作现场、`@成员` 派工、固定指派草稿、暂停与恢复（持久横幅）、固定当前协作现场。
6. 顶栏布局三档：均衡 / 阅读（Dock 收成竖条）/ 协作。

## 验收

```bash
# 任意静态服务指向本目录，默认端口 4179
node browser-check.mjs        # 33 条断言，直接对应 docs/design.md 的结构判断
node export-all-pages.mjs     # 批量导出页面截图
```

`browser-check.mjs` 的断言写成「design.md 的某一条被改掉就会红」，例如舞台宽度占比、实现与验证两列是否等宽、围栏右侧是否标了冷启动、暂停横幅在 toast 消失后是否仍然可见。当前 **44 / 44 通过**，无控制台错误。

`verify.mjs` 已删除：它是 V2 的静态标记检查，其中「预览与 Room 等宽」等断言与 V3 的结论相反，保留会误导。

## 待观察的判断

`docs/design.md` §7 记录了三条本轮明确选择、但需要真实使用验证的决定，各自写明了风险、切换信号和备选方案：
