```bash

```

另一终端：

```bash
node browser-check.mjs
```

## 最终一级工作面

竖栏是唯一一级导航，共九项：

1. 任务：日常工作的主入口。
2. 会话：独立讨论与任务会话。
3. 项目：文件、项目记忆、Skills 与项目设置。
4. 自动化：规则、运行记录与 Webhook 投递。
5. 记忆：待办、知识库与知识图谱。
6. 能力：Skills、MCP 及插件贡献的可选数据面。
7. 运行时：执行机器、adapter、接入方式、模型、工具和额度。
8. 统计：用量、监控与记忆效用。
9. 设置：应用级和工作区级配置。

任务面固定为四个视图：**概览 / 会话 / 验收 / 资源**。每个视图由主栏与可折叠副栏组成；轨迹属于会话副栏，可放大复盘，不再单设一级视图。不存在协作 Dock、编辑器标签排、底部执行面板或布局三档。

## 本版定稿的关键结论

- 执行对象是 `adapter + 接入方式 + 模型 + 思考深度`，不是虚拟“AI 成员”。
- Room 在界面上统一称“会话”；Thread 是其内部记录，不单独暴露。独立会话不产出验收或记忆，需先转成任务。
- 可信交付采用“主张 → 论证 → 证据”；同源验证不能显示为独立验证。
- 项目直接引用能力面中的 Skill；带 `steps` 的 Skill 自动标记为“编组”，不建立第二种对象。
- 自动化每次触发都回到普通任务及其证据链，不提供仅运行模式。
- 记忆按职责分流：内容在记忆，策略在设置，故障在系统诊断，价值在统计。
- 运行时只管理执行资源；停止具体执行在任务或统计 · 监控。
- 设置按作用域分成“应用 / 工作区”，同一配置只有一个可编辑入口。
- 设计稿表达最终产品完整度；“暂未实现”只能影响发布计划，不得删减最终页面的数据与操作。

## 实现使用方式

实现前按以下顺序核对：

1. 先读 `docs/personahub-prd.md`，确认当前版本范围。
2. 再读本目录 `docs/design.md`，确认对象归属和页面行为。
3. 实现具体工作面时逐条核对 `docs/implementation-notes.md`。
4. 最后用 `browser-check.mjs` 的同名断言建立生产 E2E，不把静态原型代码复制进 `web/`。

像素、动效和响应式断点可以在生产实现中调整；对象归属、状态语义、动作影响范围、唯一入口和可访问性规则不得静默改变。若要改变，先修订 PRD/ADR 与本设计基线，再重估 Feature。

视觉参考许可与声明见 `LICENSE.multica` 和 `NOTICE.multica`。
