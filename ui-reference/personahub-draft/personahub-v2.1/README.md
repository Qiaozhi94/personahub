# PersonaHub V2.1 最终态交互蓝图

> 当前 V2 设计基线：覆盖 24 个页面状态，后续 V2 评审与实现映射均以此版本为准。

这是一个独立于旧页面草图的最终产品结构提案，用静态 HTML 表达“项目优先”的 PersonaHub 工作台。它不按当前开发阶段裁剪能力，统一呈现任务、协作现场、阶段成果、验证证据、知识与自动化。

本次修订保留原 V2 的浅色视觉语言，将右侧 Room 升级为能在任务主会话与阶段协作现场之间切换的“协作 Dock”；桌面端支持均衡、专注阅读和深度协作三种布局。工作区与项目作为全局范围并列放在顶栏，只显示名称；开始中心等非项目页面也能看到当前选择。

## 打开方式

双击 `index.html` 即可使用，无需安装依赖或启动服务。

## 文件

- `docs/design.md`：页面结构、对象关系与交互原则。
- `index.html`：静态可点击原型。
- `assets/styles.css`：全部视觉样式。
- `assets/multica-theme.css`：基于冻结设计稿 token 的浅色视觉覆盖层。
- `assets/app.js`：页面切换、对象打开、Room 操作等演示交互。

## 可点击范围

1. 左侧活动栏：开始、项目、能力库、自动化、设置。
2. 项目浏览器：任务、资源、产出、知识四种对象树；任务默认置顶，提供搜索、新建、打开、重命名、归档与删除入口。
3. 中间画布：文件、任务、Room、Artifact、Evidence 等对象切换。
4. 右侧协作 Dock：任务主会话、阶段协作现场、会话概览、固定指派草稿、`@成员` 派工，以及明确影响范围的“暂停后续步骤”。
5. 底部执行面板与命令面板。

Room 概览参考 Clowder 的状态右栏，按“会话信息（含消息统计）→ Agent 状态 → 详细执行计划”排列；不再设置独立“上下文”页或低频管理操作区。等待指派时用可编辑的 `@成员` 指令完成改派，证据不足时从具体结论预填验证指令。

可信结果采用三层入口：消息结论旁的状态、中央验证依据 / Evidence Summary、左侧产出索引。Markdown 与代码文件提供修改数量、位置标签和上一处 / 下一处跳转。

顶部已经承担 Workspace / Project 范围选择，资源树不重复显示正常的“Workspace 可执行”卡片；只有运行环境异常时才应在相关会话或全局状态中提示。

## 定位

本目录是 PersonaHub 最终产品结构、对象层级和交互语义的设计基线，不是生产实现代码。实现可以调整像素与动效，但不得悄悄改变这里确定的对象归属、状态含义和操作影响范围。

视觉参考许可与声明见 `LICENSE.multica` 和 `NOTICE.multica`。
