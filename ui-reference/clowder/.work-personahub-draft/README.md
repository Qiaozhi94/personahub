双击 `pages/workbench-running.html` 即可浏览，无需启动任何服务。

> **这不是可交付原型。** 它含参考项目的视觉与素材，作用是让用户确认目标形态，说出
> 「对，就是这个」或「不对，这块不要」。它不进 `web/`，不作为实现代码
> （见 `personahub/docs/reviews/product-experience-reset-plan.md` §5.6）。

其中 `workbench-*` 是**同一张工作台的不同状态**。左栏与中栏的大结构保持不变；右栏是
当前任务的对象库：平时查文件，交付时查产物，需要人介入时处理审批，复用经验时查看记忆。

## 布局：四栏（PRD §6，2026-08-15 修订）

```text
第 1 栏 入口导航   工作区(Space)切换 · 任务 · 项目 · AI 成员 · 记忆/自动化/做法(占位) · 设置
第 2 栏 当前列表   = 第 1 栏选中入口的列表；只做定位，不承载动作
第 3 栏 协作现场   Issue-bound 会话、事件与人的动作；文件从右栏点入后在这里看全文
第 4 栏 任务资料    文件（目录/本次变更）/ 产物（来源/验证/边界）/
                    审批（待处理/历史）/ 记忆（本次引用/待沉淀）
```

右栏重构判断（2026-08-15）：

- **删除概览页**：Issue 状态、参与成员、当前阶段和下一步已由中栏标题、会话和事件表达；右栏再列一遍不会增加判断力。
- **导航来自真实使用对象**：文件、产物、审批、记忆都是会被打开和管理的对象；运行图和证据模型属于系统内部结构，不要求用户先理解架构。
- **文件面服务高频确认**：保留目录、搜索和本次变更；内容只读，点文件仍在中栏看全文，不把右栏做成第二个 IDE。
- **产物是可信交付的载体**：每个产物固定到 Run / Attempt，并附真实命令事件、独立验证身份、验证结论、证据完整性与可信边界。
- **不设独立“证据链”页**：可信度不能由一张要求表或一个分数制造；用户在具体结论旁看到原始记录、谁验证、哪些没证明，才有理由相信。
- **审批与记忆可回溯**：审批记录请求人、影响、依据和决策事件；记忆区分本次实际采用与待确认候选，并能跳回来源。

其余形态判断：

- **中栏是会话式的**，不是事件日志。工具调用与 run events **折叠进 agent 的那条消息**里
  （`执行了 3 步 · 展开看命令与耗时`），现场先回答「谁说了什么」。
- **文件以全文为主、变化着色**，项目目录树在右栏「文件」模式。人审的是「这份 PRD 现在
  写成什么样」，逐行 diff 主要服务机器与验证成员，因此不进 P0。
- **第 4 栏只在有 Issue 上下文时存在**。AI 成员、首次设置、未选中任务的列表页都没有右栏——
  右栏回答不了「这个 Issue 现在怎么样」的页面，就不该有右栏。
- **建议指派预填进输入区**，不是一排按钮：同意就发，不同意改一个词。按钮只有「照做/不照做」
  两种结果，不同意时用户得自己从头组织指令。
- **列表只有四色灯**（黄=该你动手、蓝=系统在跑、绿=完成、灰=还没轮到），不显示细分状态词。
  细分状态仍在任务内部，并继续驱动黄灯内部排序。
- **左栏顶部是 Space，不是项目**；项目信息与代码目录归项目页管理，左栏不常驻。
- **中栏不做视图 tab**：文件由右栏「文件」模式的目录树点进来，顶部「← 返回会话」。视图 tab 与
  目录树是两条通往同一处的路径，留两条只会让用户先判断该走哪条。
- **输入框结构整块取自 multica 冻结页**（contenteditable + 左下 `+` + 右下圆形发送图标），
  只换 placeholder 与图标；**不加解释性小字**，预填内容随时可改。
- **建议指派直接预填输入框**：`@建议成员 + 建议做的事`，理由放标题下那一行。
- **不显示轮次计数**：轮次不是通用名词，且上限是自动 loop 的保护装置——手动指派下用户
  自己就是保护装置。改为「连续 N 次未解决 / 未满足」这类收敛信号。
- **右栏没有消息数、token、成员卡、运行日志或显式执行图**：这些要么不支撑人的高频决策，要么与中栏重复。需要审计时从产物的原始记录进入。

## 方法：剪贴真值，不是重画

以 multica 冻结页 `issue-detail.html` 为骨架，用 `build.mjs` 做 DOM 手术：删无对应旅程
步骤的区块、改文案、换中栏与右栏内容。**不重写 CSS、不重建 token、不自造类名**——
样式全部来自 `assets/` 下 multica 编译后的真值。

区块来源分工（详见 `personahub/docs/reviews/page-sourcing.md`）：

- **multica**：视觉基准 + 左栏导航 + 列表/表单骨架
- **clowder-ai**：Workspace 的文件树、产物主从视图、审批待办/历史、记忆来源锚点与状态保持结构
- **dsh**：三列 frame、事件行（图标位 + 主文本 + 右侧耗时）、右栏「点某行才出详情」的空态

## 交互约定

- **跳转**：站内链接与 `onclick` 跳转，目标页必须存在（`verify-nav` 逐条点）。
- **页内切换**：可点元素带 `data-switch="<组>" data-target="<面板 id>"`，面板带
  `data-panel="<组>"`，一段通用脚本处理全部。右栏一级是文件/产物/审批/记忆；文件和记忆有范围切换，产物有列表/详情，审批有待办/历史与决策结果。
- **不做静默死角**：任何点了不会有变化的元素，**必须带 `title` 说明为什么**
  （例如「本轮草案未覆盖：成员详情页」）。`verify-nav` 会把没说明的揪出来——
  这条规则是为了让「草案没做」和「做坏了」永远可区分。

**AI 成员是用户创建的一层，不是 CLI**：草案里 4 个成员中有 2 个都基于 Claude Code，
只是模型参数、思考强度与能力项不同——这正是「成员 ≠ CLI」最直白的体现。
CLI 的安装与登录属于运行时配置，归设置。

`verify-draft.mjs` 的断言点直接取自旅程的「必须一眼回答」，因此它同时是**旅程覆盖检查**：
某一页删掉了关键信息，验收会红。
