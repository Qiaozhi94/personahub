# F011：Trusted Task Surface

> Owner: unassigned | Target: v0.3

## 0. 来源与意图

- PRD：第 6.1、7.3、7.4、10 节。
- 设计基线：V3.44 任务四视图。
- 上游：F006、F009、F010、ADR 0010。
- 意图：让用户从同一任务回答现状、协作、可信度和实际资源四类问题。

## 1. 问题、目标与非目标

现有页面按后端对象与聊天顺序组织，用户难以判断下一步与可信度。目标是提供概览、会话、验收、资源四视图和一致状态投影。非目标是完成运行时配置、Memory、自动化或统计工作面。

## 2. 用户场景

### US-001：判断任务下一步（Priority: P1）

用户打开任一任务即可看到目标、待决定、当前状态和下一步。

**独立测试**：至少七类任务状态使用同一 projection，首屏内容按风险变化。

1. Given 任务等待权限，when 打开概览，then 阻塞原因和允许 / 拒绝动作先于普通活动。
2. Given 任务已完成，when 打开概览，then 完成结论与非阻塞建议同时可见。

### US-002：核对可信结果（Priority: P1）

用户按完成要求查看主张、论证、证据和未覆盖项。

**独立测试**：同源验证负例不能获得独立验证状态。

1. Given 有系统事实和模型陈述，when 查看主张，then 两者信源不混同。
2. Given Artifact revision 缺失，when 查看依据，then 主张变为需处理并保留历史 ref。

### US-003：连续查看资源与轨迹（Priority: P1）

用户在资源清单就地预览多个文件，并在会话旁查看 / 放大轨迹。

**独立测试**：切换视图保留会话草稿，轨迹与资源不创建重复状态。

## 3. 范围与边界

### 范围内

- 任务头与概览 / 会话 / 验收 / 资源四视图。
- 活动、轨迹、大纲、预览四个可折叠副栏。
- 主张—论证—证据、状态筛选、未覆盖要求与 Artifact / 文件跳转。
- 异常状态的影响说明与唯一主操作。

### 范围外

- 独立会话管理、执行组合管理、Memory / 自动化 / 统计完整页面。

### 边界场景

- tab 数字只计人工待办，同一事项不可重复计数。
- 正在写入的文件不算完成成果。
- 空态不伪造进度或预计值。

## 4. 需求

### 功能需求

- **FR-001**：单一 TaskProjection 提供四视图共享事实与人工待办计数。
- **FR-002**：概览只包含目标、待决定、现状、下一步，与验收零重复。
- **FR-003**：验收按要求组织 claim / argument / evidence，并保留信源与独立性。
- **FR-004**：资源按产出 / 输入列出文件和 Artifact，并支持就地预览与来源跳转。
- **FR-005**：轨迹投影输入 / 模型 / 工具事件，可折叠、搜索、分页和放大。
- **FR-006**：异常状态显示发生、影响、建议与动作恢复边界。

### UX 需求

- **UX-001**：四视图共享一个输入框并保留草稿；主栏 / 副栏折叠不改变当前任务。
- **UX-002**：表、页签、弹窗与文件变化导航满足 V3.44 可访问性契约。

### 非功能需求

- **NFR-001**：投影可从持久状态重建，SSE replay 不重复事件或待办计数。

## 5. 生命周期与不变量

TaskProjection 不拥有状态写入权。状态来自 Issue / Dispatch / Run / Artifact / Evidence；页面动作调用各自 canonical service。失败、中断、取消、排队和验证未收敛必须保持不同终态与恢复路径。

## 6. 成功与验收

### 成功标准

- **SC-001**：用户无需打开底层日志即可判断任务现状、可信度和下一步。
- **SC-002**：从主张到原始事件、文件和 Artifact revision 可双向追溯。

### 验收清单

- [ ] **AC-001** (`FR-001`, `FR-002`, `FR-006`): 七类关键状态共用骨架且首屏按风险正确排序。
- [ ] **AC-002** (`FR-003`): 主张 / 论证 / 证据、未覆盖项和同源降级可观察。
- [ ] **AC-003** (`FR-004`, `FR-005`, `UX-001`): 资源 / 轨迹连续查看且切视图不丢草稿。
- [ ] **AC-004** (`UX-002`, `NFR-001`): 浏览器键盘、语义与 replay 测试通过。

## 7. 测试、依赖与决策

### 测试策略

Projection 单测、API/SSE 集成测试、组件状态矩阵与 Playwright 四视图旅程；从设计稿 125 条断言中提取适用生产契约。

### 依赖

依赖 F009 新壳层和 F010 Artifact 契约；读取 F006 图状态。F012 提供实际派工与会话动作，F014 负责整条旅程。

### 决策与风险

采用一个 projection 服务而不是四套查询；不复制设计稿静态数据。主要风险是旧状态字段无法完整映射，必须显式提供 unknown / legacy 状态而非猜测。
