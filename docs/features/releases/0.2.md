# Release 0.2

> 收口于 2026-08-09。产品判断以 `docs/personahub-prd.md` 为准；本文件是交付摘要，
> 不是需求真相源。逐条 FR/AC 见各 Feature 目录下 `docs/features/0.2/Fxxx-*/spec.md`
> （均为 `gate_version: 0`，不要求补齐 `tests:` 路径引用）。

## 交付范围

0.2 是 Orchestrator Workflow 的第一步：一个真实场景验证图执行（fan-out →
fan-in、显式 Node/Edge、恢复语义），一个确定性规则引擎把自然语言目标变成可复核
的执行方案建议，一个管理面把 workflow 模板和 runtime health 变成用户可读可控的
界面。三者按"一个 feature 一个主要 intent"从 PRD 第 15 节 v0.2 拆出，拆分理由见
`BACKLOG.md` 历史记录。

| Feature | 一句话意图 | 状态 |
|---|---|---|
| F006 Orchestrated Coding Graph Slice | 让一个真实 coding Issue 能被拆成至少两个独立分析节点，并通过显式边汇聚到 synthesis 节点，且执行过程可追踪、可恢复 | done |
| F007 Coordinator Agent & Routing Recommendation | 用户描述一个目标，系统给出可复核的 Issue 与执行方案建议，用户确认后才开工 | done |
| F008 Workflow Template Admin & Runtime Health | 让用户能看懂并安全地改动 workflow 模板，并能一眼看出运行时现在是否健康 | done |

## 关键设计决策（供后续 Feature 参考，详见各 `design.md`）

- **图执行不新建调度器**：物理串行由既有 workspace FIFO 队列保证；节点结果的
  唯一真相源是新增的 `graph.node_result` ThreadEvent（`EvidenceResolution` 只
  返回引用元数据，从不返回 payload），F006 `design.md` 第 8 节单独拥有跨
  feature 契约。
- **Coordinator 不派工、不新建执行通道**：v0.2 用进程内确定性规则引擎，只推荐
  不派工；执行通道决策见 `docs/decisions/0007-coordinator-execution-channel.md`。
- **确认 token 必须 HMAC 签名**：推荐阶段零写入，token 是客户端手里的唯一副本，
  没有签名服务端无法执行过期与只读字段契约。
- **模板编辑一律版本化、行不可变**：`steps_json` 是 validation 是否启用的唯一
  开关，关闭验证需要显式确认（`activate()`/`deactivate()` 两个保不变量的命令，
  不提供通用 `setStatus()`）。

## 已知限制与遗留项

- **F008 模板字段除 `steps_json`/`name` 外全无运行时消费者**：v0.2 一律只读并
  在 UI 标注，不代表已经生效。
- **UI 未做真实浏览器人工点击验证**：本环境无浏览器工具，F006/F007/F008 的
  Web UI 改动只有自动化测试覆盖。
- **v0 门禁豁免**：F006-F008 与 F001-F005 一样标记 `gate_version: 0`——F008 的
  验收清单没有 `tests:` 路径引用，`design.md` 用的是「开放项（不阻塞开发）」而
  非 v0.3 起统一要求的「待确认设计问题」，均属历史结构，不需要为此回填。
