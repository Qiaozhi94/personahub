# Release 0.1

> 收口于 2026-08-09。产品判断以 `docs/personahub-prd.md` 为准；本文件是交付摘要，
> 不是需求真相源。逐条 FR/AC 见各 Feature 目录下 `docs/features/0.1/Fxxx-*/spec.md`
> （历史 Feature，均为 `gate_version: 0`）。

## 交付范围

0.1 建立了 PersonaHub 的最小可用闭环：Project/Workspace/Issue/Thread 基础 →
下发指令给本地 CLI agent → 把执行过程沉淀为可追溯 trace → 自动验证驱动 Issue
状态流转 → 手动在多个 agent（Codex / Claude Code / OpenCode）之间路由并接力。

| Feature | 一句话意图 | 状态 |
|---|---|---|
| F001 Workspace & Issue Foundation | 建立启动 agent run 之前必须具备的最小 Project / Workspace / Issue / Thread 基础 | done |
| F002 Agent Command Center | 从 Issue primary Thread 向本地 Codex CLI agent 下发指令，观察 Run 状态、日志和事件 | done |
| F003 Development Trace | 把一次 coding Run 的命令、验证命令、文件变更和交接结果沉淀为可追溯、可查询、可导出的 trace | done |
| F004 Autonomous Validation | implementation Run 完成后自动进入 validator 检查，基于 evidence trace 驱动 Issue 到 Done/Running/Blocked | done |
| F005 Multi-Agent Manual Routing | 在 primary Thread 里手动 @ 选择 Codex/Claude Code/OpenCode 处理当前指令，自动读取上一轮 Handoff Packet 和证据作为上下文 | done |

## 已知限制与遗留项

- **F005 UI 未做真实浏览器人工点击验证**：本机环境无浏览器工具，Adapter
  Settings / Composer / Thread / Inspector 的多轮 UI 改动只有自动化测试覆盖，
  未做人工点击走查。
- **F005 收敛过程长**：Phase 13 完成后又经过 12 轮独立代码检视（round 1-12，
  原始记录已按 `docs/SOP.md` 检视文档生命周期纪律清理，只保留
  `docs/reviews/RETROSPECTIVE.md` 中的教训摘要），核心是 workspace-aware
  availability 的并发写序保护——最终方案是进程内共享单例
  `AdapterAvailabilityProbeCoordinator`（`server/src/services/adapter-probe-coordinator.ts`），
  不依赖任何新增 schema 列。这一教训（"不要给频繁变化的运行时状态加持久化列做
  CAS，优先考虑进程内 generation 计数"）已沉淀进 RETROSPECTIVE，供后续 Feature
  参考。
- **v0 门禁豁免**：F001-F005（连同同批的 F006-F008）在 `check-feature-gates`
  上线时统一标记 `gate_version: 0`，不要求补齐验收清单的 `tests:` 路径引用；
  如需升级到 v1 需逐条补齐后手动把 frontmatter 改为 `gate_version: 1`（单向）。

## 技术基线（收口时）

Schema 版本 v7（`agent_configs` + `adapter_workspace_status`）；三个 adapter
provider（Codex CLI / Claude Code / OpenCode）均已落地并完成真实 CLI 端到端验收。
