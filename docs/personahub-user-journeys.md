# PersonaHub 用户旅程

> 本文是跨 Feature 行为真相源，只定义用户目标、前后状态、反馈和恢复，不拥有页面布局。最终页面组合见 `ui-reference/personahub-draft/personahub-v3.1/docs/design.md`。

## 1. 产品承诺与边界

PersonaHub 帮助个人用户把目标交给一个或多个本地 AI CLI，在同一任务中完成派工、执行、验证和复盘。用户不需要手工搬运上下文，但始终看得到本次执行用什么、看过什么、改了什么、为何可信。

当前旅程以 coding 为首个完整切片。研究、排障、自动化和记忆复用沿用同一任务与证据链，不形成平行体系。

### 1.1 用户必须理解的概念

| 概念 | 用户需要回答的问题 |
|---|---|
| 工作区 | 这批项目、任务、Skills 和记忆归哪里？ |
| 项目 | 这项长期工作及其文件、记忆、默认 Skill 是什么？ |
| 任务 | 这次要交付并验收什么？ |
| 会话 | 我在和谁讨论、向哪里派工？ |
| 执行组合 | 这一步由哪个 adapter、接入方式、模型和思考深度执行？ |
| 上下文范围 | 这一步能看到全部过程、只看结果，还是只看目标？ |
| Skill / 编组 | 采用什么可复用做法和完成要求？ |
| 证据 | 为什么可以相信这条结论？ |

### 1.2 不应要求用户理解的概念

Thread、Dispatch ID、Run ID、Attempt、GraphRun、NodeRun、SSE cursor、SQLite 表和恢复 generation 默认不出现。只有在轨迹、诊断、导出或错误定位时渐进披露。

### 1.3 跨旅程规则

- 状态、操作确认、能力缺失使用不同反馈，不用同一种 toast 承担全部语义。
- 不能执行的选项保持可见，写明原因和替代路径。
- 高风险动作先展示会动什么、不动什么、如何恢复。
- 用户改变默认选择可以继续，但任何可信度降级必须同步可见并持久记录。
- 一次动作只在一个负责工作面提供主入口；其他位置只读展示并指向主入口。

## 2. 旅程范围与优先级

| 旅程 | 当前优先级 | 当前版本要求 |
|---|---|---|
| J1 首次配置到可派工 | P0 | v0.3 必须完整走通 |
| J2 创建并启动任务 | P0 | v0.3 必须完整走通 |
| J3 跟进、介入与恢复 | P0 | v0.3 必须完整走通 |
| J4 验收并消化结果 | P0 | v0.3 必须完整走通 |
| J5 维护项目与 Skills | P1 | v0.3 提供最小基础 |
| J6 沉淀记忆与判断价值 | P1 | v0.4 |
| J7 建立并运行自动化 | P1 | v0.4 |
| J8 盘点运行时与统计 | P1 | v0.3 基础、v0.4 完整 |

## 3. J1 · 首次配置到可派工

### 3.1 目标与终点

用户首次进入后建立最小工作区、项目、代码目录和执行资源。终点不是“保存成功”，而是至少一个执行组合明确显示可派工；如果做不到，用户知道具体原因和下一步。

### 3.2 主路径

1. 创建或确认工作区。
2. 创建项目并添加主代码目录。系统解析真实路径；如果是 Git 仓库，自动读取 remote 与执行机器上的提交身份。
3. 选择该目录在哪些执行机器上可读写；参考仓库只允许只读。
4. 检查机器上的 adapter。CLI 自管登录时显示状态和终端登录命令；只有 PersonaHub 真正持有 API Key 时才出现密钥输入。
5. 展示 adapter 在线状态、接入方式、可用模型、思考深度、工具和额度。
6. 生成执行组合清单，并明确哪些可派工、哪些不可派工以及原因。

### 3.3 错误与恢复

- 路径不存在或解析到未授权真路径：不保存授权，保留输入并定位错误。
- Git remote 不存在：允许作为纯本地目录继续，明确说明拿不到远端 PR / issue。
- CLI 未登录：不伪装为 adapter 故障；给终端命令和重新检查动作。
- adapter 离线：组合不可选但仍展示；不自动换另一个模型。
- 额度不足：本次不可派工，显示重置时间；不算系统故障。
- 检查失败：保留已完成步骤，重试只重跑失败检查。

### 3.4 高风险动作

撤销路径授权、删除接入方式、暂停全部派工时，确认中必须列出影响对象、不会改变的历史和恢复入口。历史 Run、证据和验收结论一律不随配置删除。

## 4. J2 · 创建并启动任务

### 4.1 目标与终点

用户从一段自然语言目标创建可验收任务，并在理解执行组合、上下文、Skill 和权限后发出第一轮派工。

### 4.2 主路径

1. 用户输入目标，可选项目、标签和 Skill；不要求先想标题。
2. 系统整理但不替换目标原文，展示建议的完成要求与执行路径。
3. 派工时模型和思考深度分开选择；候选分建议、可选、不可选，每行说明原因。
4. Skill 与当前步骤提供的能力要求取并集，并逐项显示来源。
5. 系统按任务目的预选上下文范围，并展示将包含 / 过滤的内容。
6. 用户确认后原子创建任务与首个会话；重复提交只创建一次。
7. 派工进入短暂可撤销状态。撤销窗口结束且执行记录建立后，任务进入排队或执行中。

### 4.3 空态与错误

- 目标为空：不生成推荐、不创建任务。
- 没有可用组合：保留草稿并引导到运行时，不创建一个永远无法开始的 Run。
- 可选组合不满足软性能力要求：允许使用，但在派工记录、成果来源和验收中持续标注。
- 验证组合与实现同源、adapter 无法隔离原生记忆、登录未知或额度不足：不可选且不隐藏。
- 创建事务失败：不留下孤儿任务、会话或事件；再次提交可安全重试。

## 5. J3 · 跟进执行、介入与恢复

### 5.1 用户需要持续回答的问题

1. 现在处于哪一步，谁在执行？
2. 已经产生了什么实际变化？
3. 当前是在正常运行、排队、等待我，还是发生故障？
4. 我现在能做什么，动作会影响什么？

### 5.2 正常路径

- 概览展示目标、当前状态、待决定事项和下一步。
- 会话展示用户与执行组合的原文；轨迹展示输入、模型、工具、耗时和上下文血统。
- 资源持续列出输入与产出；正在写入的文件不计为已完成成果。
- 验收随执行累积证据，但未覆盖的要求始终可见。
- 阶段结束后自动形成 Handoff Packet；下一次派工引用确定 Artifact revision，不依赖复制聊天全文。

### 5.3 人工介入

- 补充指令：进入当前会话，形成新事件。
- 改派：只影响尚未开始或下一次派工；已经运行的 Attempt 不热换执行者。
- 暂停后续派工：不启动新的 Attempt，不杀死已经运行的进程；恢复后按新约束重新判断资格。
- 取消当前执行：只结束目标 Attempt；此前已确认产出和证据保留。
- 修改上下文范围：产生新派工，切换范围必须冷启动；验证改回“全部”时降低独立性。

### 5.4 异常恢复

| 状态 | 用户看到什么 | 主恢复动作 | 必须保留 |
|---|---|---|---|
| 已排队 | 等待哪把写锁、当前位置 | 继续等待或取消 | 原派工与队列理由 |
| 等待权限 | 哪项操作、路径和风险被拦 | 允许或拒绝 | 阻塞前产出 |
| 执行失败 | 失败步骤、原始错误、影响 | 重试或换组合 | 已完成步骤、失败证据 |
| 已中断 | 重启前 Attempt 作废 | 从中断步骤新建 Attempt | 已完成步骤，不重复执行 |
| 已取消 | 明确由用户停止 | 重新开始新 Attempt | 取消前变化与证据 |
| 验证未收敛 | 每轮 findings 与重复模式 | 换策略、改派或人工裁决 | 每一轮结果，不合并覆盖 |

失败不写成中断，中断不写成完成，取消不计故障，排队不计故障。恢复永远新建可追溯记录，不改写旧记录。

## 6. J4 · 验收并消化结果

### 6.1 目标与终点

用户能回答“做成了什么、为什么可信、还有什么风险”，并从结论追到原始事件与实际文件。终点是所有必要主张满足或用户明确接受剩余风险，而不是进度数字达到 100%。

### 6.2 主路径

1. 打开验收，按完成要求查看主张树。
2. 每条主张展开论证、执行证据、测试、文件 / Artifact revision 和验证者结论。
3. 状态卡可筛选已独立验证、有证据待验证、需要处理；再次点击取消筛选。
4. 查看验证者使用的执行组合、上下文范围和被过滤内容。
5. 对未覆盖要求补证据、重新派验证或明确接受风险。
6. 通过后生成不可漂移的完成摘要 revision，任务进入完成。
7. 验证者的非阻塞建议继续保留，可转成新任务。

### 6.3 边界

- 同源验证只能显示“有证据待验证”，不能获得独立验证符号。
- 证据缺失、文件哈希变化或 Artifact revision 不可读取时，原结论降为需要处理，不用最新文件顶替历史。
- 验收基线修改要在执行前确认并留事件；执行中新增证据不需要阻断。
- 实现回归与端到端验收分开，任何一方不能代替另一方。
- 完成后发现问题时，新建修复任务或重新打开并产生新 Attempt；历史完成摘要不覆盖。

## 7. J5 · 维护项目与 Skills

### 7.1 项目

用户在项目中浏览文件、当前项目作用域的 Memory、引用的 Skills 和项目设置。项目记忆是全局知识库的筛选视图；项目 Skills 直接引用能力面对象。

项目只配置一个可写主目录、多个只读参考仓库和文件范围。网络、`git push`、通知、模型、记忆策略不在项目中重复设置。

### 7.2 Skills 与编组

用户可以查看 Skill 的 `id@version`、来源、能力要求、下发状态和文件。带步骤的 Skill 自动标为编组。编辑磁盘文件或创建新版本，不在详情里直接覆盖历史版本。

同名冲突在生效前处理；系统不静默覆盖。编组表现只显示带样本量的观察，不形成评分或排行榜。

## 8. J6 · 沉淀记忆与判断价值

1. 只有收敛的验收事件可以产生候选；普通对话不自动摘取。
2. 待办把候选、复核和整理建议互斥分组，每条都有动作。
3. 人工确认才能把适合长期约束的内容升为 `confirmed`。
4. 待复核内容退出召回；过滤原因在任务上下文与召回预览中可见。
5. 设置中的“试一次召回”读取未保存草稿，列出带入 / 过滤项、原因和 token 占用，但不写使用记录。
6. 知识库和知识图谱双向定位；冲突不自动消解。
7. 统计分别展示展示、引用、采纳和帮助证据，用户据此决定保留、复核或退役。

## 9. J7 · 建立并运行自动化

1. 用户选择定时或 Webhook 触发，使用结构化时间选择器或用户语言的入口规则。
2. 选择当前可派工的模型与思考深度，并编辑一份 Markdown 任务内容。
3. 确认后保存固定 revision；每次触发不重新改写规则。
4. 入口验签 / 去重 / 过滤通过后再检查额度、登录态和项目权限。
5. 通过则创建普通任务；未通过记录“未触发”并在需要时通知。
6. 运行结果回到任务验收链。手动重跑创建新运行记录与新任务。

自动化暂停只阻止后续触发。公网投递正文不可扩大权限。验证失败属于任务结果，基础设施错误才属于自动化执行失败。

## 10. J8 · 运行时与统计

### 10.1 运行时盘点

用户先选择执行机器，再比较 adapter。机器状态取其 adapter 最坏状态；具体原因在 adapter 行和详情中查看。工具表同时列 CLI 内置工具与 MCP 实际注入结果。

运行时的“运行中”只读。具体停止动作在任务或统计 · 监控；全局暂停派工是资源准入操作，保留在运行时。

### 10.2 使用与故障复盘

- 用量按任务去向和用途查看，API 实付与订阅等价分开。
- 监控只收执行中、排队和真实故障；基础设施去系统诊断。
- 从统计任务行进入任务轨迹查看逐次调用，不在统计里重复造详情。
- 记忆效用四层分开，不合成总分。

## 11. 跨旅程状态矩阵

| 事件 | 任务 | 会话 | Run / Attempt | Artifact / 证据 |
|---|---|---|---|---|
| 确认创建 | 刚创建 | 首个会话存在 | 尚无 | 完成要求基线已固定 |
| 派工可撤销期 | 刚创建 / 等待启动 | 有派工草稿事件 | 尚未建立 | 无 |
| 排队 | 已排队 | 保留可输入 | queued | 无或保留上阶段成果 |
| 执行 | 执行中 | 流式追加 | running | 新产出标进行中 |
| 阶段完成 | 等待指派或继续图 | Handoff 可见 | terminal | 新 revision 固定 |
| 验证未通过 | 验证未收敛 | findings 可继续讨论 | validator terminal | 旧改动和失败证据保留 |
| 中断 | 已中断 | 恢复说明可见 | running → interrupted | 已完成 revision 保留 |
| 取消 | 已取消 | 取消事件可见 | target → cancelled | 取消前事实保留 |
| 通过 | 已完成 | 可继续讨论 | terminal | 完成摘要固定 |

## 12. 可观察验收指标

- J1：无需文档外指导即可得到至少一个可派工组合；失败项均可恢复或明确不可恢复。
- J2：目标原文保留，确认前零写入，重复提交无重复任务，派工撤销期真实有效。
- J3：六类异常状态可分别进入并按各自路径恢复，重启不重复已完成步骤。
- J4：每条必要主张能定位依据，同源验证永不显示为独立验证。
- J5：项目不复制 Memory / Skill / 代码仓真相，所有详情可回到唯一管理入口。
- J6：Memory 过滤可见、复核退出召回、效用四层可分别下钻。
- J7：每次有效触发都产生普通任务；入口拒绝不产生 Run。
- J8：额度、用量、执行故障、应用故障四种口径不混屏。

上述指标必须有真实浏览器 E2E；组件测试不能代替完整旅程验收。
