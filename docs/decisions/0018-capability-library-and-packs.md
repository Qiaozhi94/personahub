# 0018: 能力库——Skills、插件、MCP 与信任边界

## 背景

PersonaHub 需要让方法可复用、外部数据可接入、能力可扩展，但三者的权限完全不同。早期方案把零代码目录称为“能力包”，又同时保留 Skill、Squad 和插件，造成对象重叠。V3.44 最终检视已删除“能力包”和独立 Squad：方法统一为 Skill，含 `steps` 的 Skill 标为“编组”；需要安装代码或贡献额外 surface 的发行单位称插件。

本决策回答四个问题：能力面放什么、插件能贡献什么、贡献如何进入执行与证据、哪些能力必须后移。

## 决策

### 1. 三个产品概念

| 概念 | 职责 | 不负责 |
|---|---|---|
| Skill | 可版本化的方法、能力要求、可选步骤与完成要求 | 不运行任意代码，不成为人格或成员 |
| MCP | 声明希望注入的外部工具；由 adapter 实际注入 | 不证明工具本次真的可用 |
| 插件 | 需要安装的扩展，可贡献声明式数据、外部连接、adapter 或能力面 tab | 不绕过宿主权限与证据链 |

能力面是一级工作面，包含 Skills、MCP 以及启用插件贡献的可选 tab。插件的发现、授权、启停和卸载只有设置 · 插件一个编辑入口。

### 2. 没有“能力包”产品对象

可分享的纯方法直接导入 / 导出为 Skill revision 或一组带来源 manifest 的 Skills。导出默认不含 Memory 正文、Evidence、凭据、项目路径或历史 Run。需要带代码、外部进程或 surface 的内容必须打包为插件，并走更高风险的安装与授权流程。

项目只保存 Skill refs，不复制 Skill 内容；Dispatch 固定当次 `id@version`、内容摘要与生效能力要求。Skill 升级不改写历史执行。

### 3. 三档信任

| 档位 | 内容 | 权力 | 准入 |
|---|---|---|---|
| T0 声明式 | Skill、steps、完成要求、声明式表格数据 | 影响上下文与验收，不直接执行 | schema 校验；未知字段 fail closed |
| T1 引用式 | MCP 声明、定时入口、checker 等宿主资源引用 | 只能调用已注册白名单 | 白名单 + 逐项授权 |
| T2 代码 | adapter、外部进程、数据连接插件 | 与本机用户接近同权 | 本地安装 + 风险逐项确认 |

PersonaHub 当前没有插件沙箱。因此 T2 不能被描述为“安全隔离”；启用前必须显示文件、网络、进程、密钥等实际权限。远程 marketplace、签名信任链和自动安装不在当前承诺内。

### 4. 插件 surface 只能声明，不能携带前端代码

插件可以声明能力面中的数据 tab；宿主用固定组件渲染。声明至少包含稳定 ID、标题、数据 schema、空态、错误态和白名单动作引用。

硬约束：

1. 该插件缺失时，创建任务、派工、验收和恢复等核心旅程仍可完成。
2. action 只能引用宿主注册表，例如归档条目或创建普通任务；插件不能直接写核心表。
3. 插件不得提供同源 React / JS、任意 HTML 或 DOM hook。
4. adapter 是核心派工依赖，不能通过可选 surface 声明自身管理页；其状态归运行时。
5. 插件 tab 停用后从能力面消失，但历史任务、Artifact 与 Evidence 仍保留来源标识。

### 5. MCP 的声明与事实分开

Skill 或插件可以声明需要哪些 MCP server，但 PersonaHub 不把声明当成已注入。adapter 负责把配置转换成自身协议；运行时工具表展示该 adapter 本次检查到的实际注入结果。两者不一致时：

- 派工 eligibility 写明缺失工具与影响；
- 硬要求不满足则不可选；
- 软要求偏离需用户确认，并固定到 Dispatch；
- Evidence 使用实际工具事实，不使用意图声明。

MCP 注入排在 v0.8。此前只允许保留向后兼容的字段，不提供假开关。

### 6. 五条治理不变量

1. **声明不等于授权**：manifest 只产生候选，校验、授权和激活后才生效。
2. **一个资源一个激活入口**：Skill、插件、MCP 各自由唯一 service 管写入；插件不得自建旁路。
3. **所有权与失败局部化**：每条贡献带 source / version；跨来源冲突直接拒绝；一个来源失败不拖垮其他来源。
4. **agent 可见即已记录**：所有进入上下文的 Skill、MCP 声明、外部资料与权限说明都必须能从事件和 refs 重建。
5. **只可加严，不可放宽**：插件和 Skill 不能绕过路径授权、同源验证、Memory 白名单、Evidence 来源或宿主动作白名单。

扫描顺序必须确定：候选按 ID 排序；目录名与 manifest ID 一致；保留 ID 拒绝；跨来源命名冲突在激活前失败，不静默覆盖。

### 7. 生效组合必须可见

每次派工前后都能回答：用了哪些 Skill revisions、哪些步骤、哪些能力要求、哪些 MCP 声明、哪些插件贡献，以及每项来自哪里。被过滤、缺失或用户覆盖的项也要记录原因。

生效组合是 Dispatch / Trace 的只读证据投影，不是另一套可编辑配置。

### 8. 生命周期

```text
发现 → 校验失败
   └→ 待授权 → 已安装未启用 → 已启用 → 局部失效 → 已停用 → 已卸载
```

状态按贡献项保存，插件总状态派生。停用只影响新派工；卸载移除本机文件，但不得删除历史 revision、来源快照和墓碑。升级创建新版本，不能原地覆盖已消费内容。

## 分期

- **v0.3 / F013**：Skill revision、steps / 编组、项目 refs、来源与冲突基础。
- **v0.4**：从可信验收产生 Skill 候选；仍由人确认版本。
- **v0.8**：声明式插件 surface、MCP 注入、外部协议与本地插件安装治理。
- **远期**：只有出现真实分发与第三方作者需求后再评估 marketplace、签名和隔离运行时。

## 不做什么

- 不恢复能力包、Squad 或第二套 Workflow 对象。
- 不允许社区文本原样成为系统级指令；声明先解析为宿主 canonical block。
- 不允许插件贡献新的 Evidence ref 语义；ref 构造与解析由核心注册表拥有。
- 不允许插件直接创建 run-only 自动化；执行必须回到普通任务。
- 不承诺插件热卸载、权限沙箱或远程自动更新。

## 后果

方法、工具意图和代码扩展拥有不同名字与准入风险；任何扩展仍能进入统一 Dispatch、Artifact 与 Evidence 链。代价是插件能力开放较晚，且 T2 在没有沙箱时必须诚实地暴露高权限风险。
