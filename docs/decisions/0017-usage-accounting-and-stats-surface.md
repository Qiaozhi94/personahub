# 0017: 用量记账与统计工作面

## 背景

最终设计必须同时回答三类不同问题：过去把资源花在哪里、现在有哪些任务需要处理、记忆是否真正产生价值。它们都属于复盘，但数据来源、时间语义和可执行动作不同。

另外，订阅额度、API 真实支出和按公开 API 价折算的订阅等价成本不是同一口径；PersonaHub 也已取消可治理的“AI 成员”与独立 Squad，因此不能照搬按智能体排行榜的统计方式。

## 决策

### 1. 统计是一个一级工作面，固定三个视图

```text
统计
├─ 用量
├─ 监控
└─ 记忆效用
```

- **用量**回答过去一段时间的 token、成本与用途。
- **监控**汇总执行中、排队和真实故障，并提供到任务的恢复入口。
- **记忆效用**分别展示记忆被展示、引用、采纳和证明有帮助的事实。

系统基础设施、数据库与配置问题属于设置 · 系统诊断；adapter 登录、工具、额度和机器状态属于运行时。统计不复制这些真相源。

### 2. 用量主维度是去向与用途

| 维度 | 回答的问题 | 主要动作 |
|---|---|---|
| 任务 / 项目 | 资源花在了什么目标上 | 打开任务复盘或调整范围 |
| 派工用途 | 花在实现、验证、返工还是上下文重传 | 调整 Skill、验收要求或上下文范围 |
| 执行组合 | 哪种 adapter + 接入方式 + 模型 + 深度产生该笔事实 | 为下次派工提供估算依据 |
| 上下文范围 | 全部 / 只给结果 / 只给目标的输入差异 | 调整下一次派工 |

不按角色、AI 成员或编组做排行榜。编组只允许显示带口径和样本量的局部观察，不进入统计排行。

### 3. 三种金钱 / 额度口径永不相加

| 口径 | 含义 | 位置 |
|---|---|---|
| 额度 | 上游时限额 / 周限额及重置时间 | 运行时与派工选择器 |
| API 实付 | API Key 路径产生的真实支出 | 统计 · 用量 |
| 订阅等价 | 按公开 API 价格折算，仅供比较，不是账单 | 统计 · 用量 |

走订阅的 token 不伪装成真实支出；走 API Key 的调用不伪装成订阅额度。额度只展示上游百分比与重置时间，不折算为“还能派几次”。

### 4. 成本来源和缺失值必须诚实

`cost_source` 区分 adapter / provider 自报的 `authoritative` 与本地价表的 `estimated`。同一聚合桶同时存在两者时分别汇总，不用权威部分覆盖估算部分。

adapter 没有回报 usage 时保存 `NULL`，不能保存 `0`。界面以 `—` 表示未知，并说明当前总计未覆盖多少 Attempt；不得让缺失数据静默降低总量。

Token 原始字段至少保留 input、output、cache read 和 cache write。展示可合成“缓存命中 / 未命中”，但合计必须能与原始字段对账。

### 5. 一张事实表，不预建 rollup

```text
run_usage   一行 = 一次 Attempt × model
  attempt_id / run_id / dispatch_id / issue_id / project_id
  adapter / access / model / depth / context_scope / step_kind
  input_tokens / output_tokens / cache_read_tokens / cache_write_tokens
  cost_micro_usd / cost_source / billing_mode / priced_at
  started_at / ended_at
```

本地单用户、SQLite 规模先直接 `GROUP BY` 并建必要索引；没有真实规模证据前不引入物化 rollup、cron 或 dirty queue。价表带来源与核对时间，历史行按写入时价格固化，不因价表更新重算。

### 6. 监控只收可操作的执行事实

监控列出执行中、排队与真实故障；取消不是故障，中断与失败分开，额度不足和自动化入口拒绝也不伪装成执行失败。每行主动作进入任务；停止具体 Attempt 复用任务控制服务，不在统计新建写路径。

### 7. 记忆效用不合成总分

记忆被检索展示不等于被引用，被引用不等于采纳，被采纳也不自动证明有帮助。四层分别计数、展示来源和样本量。复核、退役等治理动作仍回到记忆工作面。

## 实现门槛

完整统计排在 v0.4。在承诺精确成本前，必须先对每个 adapter 做 usage probe，并固定：字段映射、缺失语义、计费模式和 `step_kind` 判定。日界默认使用应用设置的本地时区；改变时区不得改写原始时间。

## 不做什么

- 不做成员、角色或编组排行榜。
- 不把实时额度放进统计。
- 不把系统诊断放进监控。
- 不将记忆效用压成健康分。
- 不因价格变化回算历史账。
- 不为尚不存在的多租户规模提前建聚合层。

## 后果

收益是所有数字都能追到一次 Attempt，并对应一个明确入口；代价是三个 adapter 的采集能力与成本精度可能不同，界面必须持续披露缺失和估算。
