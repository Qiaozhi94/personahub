# AI 对话归档（Conversation Archive）

把某项目在本机三大 AI CLI（OpenCode / Claude Code / Codex CLI）中的全部会话归档成
Markdown，并生成供 AI 复盘用的血缘树、时间线、复盘概览三个视图。数据源与目标项目
解耦：脚本自动从用户主目录定位各 CLI 数据，项目路径通过参数指定（默认当前工作目录），
因此**可直接复用于任意新项目**。

## 两个脚本

本 skill 携带两个可移植脚本（在 `scripts/` 下）：

| 脚本 | 作用 |
|---|---|
| `export_conversations.py` | 从各 CLI 原始数据导出会话 md（原始数据 → 会话文件） |
| `build_retrospective.py` | 从会话文件生成三个视图（会话文件 → index/timeline/retrospective） |

数据源位置（自动从 `Path.home()` 定位，跨平台）：
- OpenCode：`~/.local/share/opencode/opencode.db`（SQLite）
- Claude Code：`~/.claude/projects/<project-encoded>/*.jsonl`
- Codex CLI：`~/.codex/sessions/**/rollout-*.jsonl`

## 工作流

在目标项目目录下执行（当前工作目录即目标项目<truncated omitted_approx_tokens="189" />发/收集等）
├── retrospective.md    # 按主工作流分组的复盘概览（工具/模型/token/成本/子代理）
├── opencode/           # OpenCode 会话
├── claude/             # Claude Code 会话
└── codex/              # Codex CLI 会话
```

## 维护：幂等全量重导

项目未完成、会话会持续增长时，无需任何增量逻辑——每次全量重导，天然幂等：

1. `export` 每次清空各工具子目录再全量重写会话（秒级），新增会话后重跑即纳入；
2. `build` 从会话 frontmatter 重建全部视图，与数据源解耦，任何新会话自动进入各视图。

这保证了归档始终与最新会话保持一致，零手工维护。

## 复盘用法

让 AI 以 `conversations/index.md` 的血缘树定位工作流，用 `timeline-summary.md` 还原
多代理穿插次序，用 `retrospective.md` 看每个工作流的工作量与派生子代理；需要细节时
再深入对应会话文件。frontmatter 的 token / cost / model 可做工作量与成本分析。

## 会话文件格式

每个会话 `*.md` 含 YAML frontmatter（`tool` / `model` / `created_at` / `updated_at` /
`tokens_input` / `tokens_output` / `cost`，及可选的 `parent_id`、`thread_id`）与结构化
正文（`## user/assistant` 分段、`- **tool**:` 工具调用、`<details>` 折叠工具输出）。

## 编排级事件识别

`build_retrospective.py` 内置 `ORCHESTRATION_TOOLS` 集合（task/spawn/agent/followup/
background_output/background_cancel 等），`--summary` 时只保留这些编排级事件 + 会话
起止，用于快速呈现「A 写 → B 检视 → A 改」的穿插协作。需要增删编排工具时改这一处即可。
