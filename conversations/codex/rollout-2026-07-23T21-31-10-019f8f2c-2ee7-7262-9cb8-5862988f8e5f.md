1. 创建 adapter

   - `resolveExecutable()` 成功只写 `Unknown`。
   - 命令不存在才写 `Unavailable`。
   - UI 显示“未验证”，并提供醒目的 Validate 操作。

2. 默认 adapter

   我建议允许 `Unknown` adapter 被设为 default，但不允许它执行。

   - Project 可以记住用户选定的 default。
   - dispatch 时仍要求目标 workspace 下状态为 `Available`。
   - 未验证时返回“默认 adapter 尚未验证”，而不是偷偷选择其他 adapter。

3. 编辑 adapter

## 问题二：workspace 级 availability

我建议不要再尝试用一个 adapter 全局状态表达多个 workspace 的可用性，而是新增独立表：

```sql
CREATE TABLE adapter_workspace_status (
  adapter_config_id TEXT NOT NULL,
  workspace_id TEXT NOT NULL,
  status TEXT NOT NULL,
  last_checked_at TEXT,
  auth_status_message TEXT,
  adapter_revision INTEGER NOT NULL,
  PRIMARY KEY (adapter_config_id, workspace_id)
);
```

核心规则：

### 1. 路由必须携带 workspace

将解析接口调整为：

```ts
resolveAdapter({
  projectId,
  workspaceId,
  explicitAdapterId,
});
```

resolver、默认 adapter 路由、ValidatorSelector 都查询：

```text
(adapter_config_id, workspace_id)
```

只有目标 workspace 对应记录为 `Available` 才允许创建或启动 Run。

### 2. Validate 必须明确 workspace

接口收紧为：

```http
POST /api/adapters/:adapterId/validate
{
  "workspace_id": "..."
}
```

UI 的 Validate 应先选择 workspace，或者从当前 Issue/Workspace 上下文自动带入。

Adapter Settings 可以展示：

```text
OpenCode
├─ Workspace A：Available
├─ Workspace B：Unavailable
└─ Workspace C：Not validated
```

### 3. 失败只影响当前 workspace

某个 Run 因认证或环境问题失败时，只更新：

```text
(adapter_config_id, failed_run.workspace_id)
```

不能再把 adapter 的全局状态写为 `Unavailable`。

### 4. adapter 配置变化后统一失效

adapter 的 command、认证或模型配置改变后，应删除相关 workspace 验证记录，或者增加 `adapter_revision`：

```text
adapter revision: 6
workspace validation revision: 5
→ 状态视为 Unknown
```

我更推荐 revision，既保留历史信息，也能防止并发 probe 的旧结果覆盖新配置。

### 5. workspace 隔离设置变化后失效

`push_credentials_enabled` 改变时，仅让该 workspace 的 adapter 验证结果失效，要求重新 Validate。

### 6. 全局 `adapter.status` 的处理

最干净的方案是停止让它表示“运行可用性”，改成配置层状态，例如：

```text
InvalidConfig
Configured
Disabled
```

真正的运行可用性全部来自 `adapter_workspace_status`。

```text
全部 workspace Available → Available
存在 Available           → PartiallyAvailable
都未验证                  → Unknown
全部失败                  → Unavailable
```

不过汇总状态容易继续产生歧义，长期建议删除。
